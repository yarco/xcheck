# Multi-Agent Cross-Check Protocol

X-Check fans one immutable review packet out to **other** agent CLIs (Codex, Claude Code, Grok, Agy) as real processes, collects one answer file per lane, and leaves judgment to the orchestrating model. Codex and Claude run their own first-party headless streams and every other lane is an ACP session driven by acpx; one lane runner serves two placements: **headless** (child processes) and **Herdr** (one visible pane per lane, right of the orchestrator, showing that lane's stream).

| Owner | Holds |
|---|---|
| This note | packet contract, invariants, harness facts and why they hold, limits, merge rules |
| `bin/xcheck` + `xcheck/` | everything with one mechanical right answer: exact argv, process groups, deadlines, capacity, locks, placement, stream parsing, validation, status |
| The orchestrator | judgment: roster, packet, diagnosing a failed lane and telling the operator, premise checks, adjudication, `CONSENSUS.md` |

The code never judges a finding and never retries a reviewer turn; the model never improvises process control. Exact flags live only in `xcheck/adapters.py`; this note records why each non-obvious one is there.

Scope: one operator, one macOS machine, attended runs, possibly several orchestrator sessions running cross-checks at once. Reboot mid-run, adversarial peers, and unattended multi-hour recovery are outside the contract.

## Preconditions and source authority

Before launch, use the installed runtime matching the source (`doctor`), the real orchestrator kind, a fresh BASE under `/tmp/agent-offload`, and a valid whole-file packet. Selected peers need their native CLI/server and existing subscription or provider login. Check provider data terms before sharing the packet. These are readiness conditions, not permission to repair accounts, enable billing, lower effort or replace a model automatically. A doctor failure is a named coverage gap; report it and use lane admission to distinguish a blocked selected lane from healthy peers.

The host must retain a wait or provide a verified completion callback to promise automatic return. Without either, detach and report collection pending. Grok orchestration additionally requires verified Herdr placement; other orchestrators use auto placement. Applicable native startup/model readiness and capacity checks run again at lane admission; `doctor` separately checks the whole pinned roster. A previous smoke, doctor result or successful review is not present admission evidence.

| Question | Authority and refresh rule |
|---|---|
| What is selected? | `adapters.py` defines defaults and the Devin pin; the free OpenCode lanes come from the daily refresh's `~/.local/state/xcheck/free-roster.json`; `BASE/run.json` records this run's exact selectors, efforts and settings. Default-roster edits are deliberate |
| What can launch now? | Fresh native startup/model inventory and capacity checks under admission; failed reads mean unknown, not absent |
| What is free now? | Live provider prices and served IDs from `xcheck models`; no saved-price fallback. The free roster is that day's lane-check result, never a price source. Native client cache is advisory support metadata only |
| What did peers review? | `BASE/.packet`, captured at launch; later edits to inputs or reused lane workspaces cannot revise it |
| Is a lane live or complete? | Kernel liveness locks and the authoritative lane `exit.json`; status is derived, and native progress, PIDs and pane text are diagnostic |
| What did the review establish? | Settled native streams/results plus the host's premise checks in `CONSENSUS.md`; record scope, limitations and dated evidence |

Keep durable instructions in this Markdown note and version-specific integration documentation. Date availability/price observations and name the provider or CLI version; never read “latest”, “free” or “working” as a permanent guarantee. Recheck after upgrades and before qualification. Captured fixtures are regression inputs, not live inventories. Store run evidence under BASE, not in the vault; a past review must not become a new packet's current-state claim.

## Run it

```bash
xcheck doctor                                              # installed copy, flags, model pins
xcheck run --base /tmp/agent-offload/<slug> --orch claude  # default roster minus the orchestrator's harness
```

`xcheck` on PATH is `~/.local/bin/xcheck`, a read-only, content-addressed copy that `bin/xcheck install` publishes from this repo. `doctor` compares it with the source digest even when invoked through the copy. Reinstall after changing `bin/` or `xcheck/`.

1. **Stage** `BASE=/tmp/agent-offload/<slug>/` (Packet below). Stage and launch before loading unrelated material: every later return re-sends the whole context.
2. **Record** BASE, roster and the exact command in the existing task tracker or chat before spending. `run.json` persists the settings; write no separate handoff for a run.
3. **Announce**: `Fan-out: N peers → <lanes>. Not peers: <harness> (<why>)`.
4. **Run** without spending master-model turns: retain one blocking host operation or background job with a real completion callback. The local supervisor waits without inference. Do not schedule repeated short waits or model health prompts. Progress inspection may read only `xcheck activity` metadata; keep active findings, tool outputs and answer drafts unseen until settlement. Host notifications, repeated tool returns and large metadata outputs are not evidence of zero token use. A local wait invokes no model; subscription savings require a retained operation or verified completion callback without periodic model resumption.

   | Orchestrator | Form |
   |---|---|
   | Claude Code | `xcheck run …` as a background shell job; its completion notice is the one return |
   | Codex | absolute `~/.local/bin/xcheck run …` in a retained host shell operation, or `--detach` followed by one retained `xcheck wait --base B`. Keep shell polling inside the host tool, without returning to model sampling. The allow rule covers the installed absolute path followed by `run`, `wait`, `status`, `activity`, `cancel`, `doctor`, `capacity` or `models`; never point it at the vault source |
   | Grok | Herdr mode only. Background `xcheck run`, then retain its host completion operation; reaching a host wait cap detaches the waiter, never the reviewer |
   | opencode | In a persistent V2 TUI/web/desktop session, launch `xcheck run … --detach`, then invoke one `xcheck wait --base B` through the native `shell` tool with `background=true`. Completion inserts the shell output into the session and automatically resumes the host (verified on 2.0.27, with no polling). A one-shot `opencode run --standalone` exits at its first idle response and cannot retain this callback; use a retained foreground wait there or disclose BASE pending. `--orch opencode` drops opencode lanes |
   | pi | retain a host background completion job if available; otherwise detach and report BASE pending. Never pi's own delegate/subagent tools as peers |
   | Agy | retain a host completion job; `--orch agy` drops every Agy lane |
   | Devin | retain a host completion job; `--orch devin` drops Devin lanes |
   | anything else | `--orch other`; one retained wait/completion callback. Without that capability, detach and disclose pending collection. Never claim a different harness to bypass exclusion |

   `wait --timeout S` is for an explicit bounded status request. Exit 3 means still pending, and authorizes neither reviewer cancellation nor another scheduled master turn. `.done` is a durable completion record, not a host notification transport. Verify the host callback or retained-operation behavior; do not claim automatic resumption from a file write alone.

5. **Report** every non-`done` lane in the next chat message from `STATUS.json` (`reason`, `stderr_tail`): `<lane> <status> — <cause in plain words>. Fix: <remedy>. Continuing with <others>.` Also report MCP startup warnings and retrieval-policy diagnostics, including those on `done` lanes. Native completion and proof do not certify policy compliance; a successful unapproved call does not establish a charge.
6. **Merge** (below) into `BASE/CONSENSUS.md`.

`run` options: `--lanes kind:model[:effort],…` replaces the roster (Agy and Devin take no effort, OpenCode's is an optional ACP effort; every other kind needs one); `--add LANE` appends an opt-in lane to it. `--mode auto|headless|herdr` (default `auto`: visible Herdr panes when the caller verifies, else headless). Leave it unset; `--mode headless` is for an operator request or a placement smoke, never an orchestrator's preference, because it hides lanes the operator expects to watch. `--web live` (default: peers may search and must cite what they relied on) or `packet` (built-in web tools off and peers told not to fetch; connected MCP tools remain, so this is not isolation). `--idle` and `--cap` are optional operator-requested cancellation limits; neither has a default. The caller must not invent a limit to guess how long a reviewer should take. Without a limit, a quiet lane and a queued lane remain pending until completion, an observed failure or explicit cancellation. A supplied `--cap` also bounds pool admission and arms the runner's watchdog; its expiry means policy stopped the work, never that the reviewer was idle. Silence cannot establish inactivity. `--force-lane NAME` launches a selected lane past a capacity refusal, only on the operator's say-so and announced in chat. `--skip-capacity` is for controlled smokes. `--detach` returns once launch is confirmed; if preflight outlasts its 30-second observation window, it reports a live supervisor with launch unconfirmed. A reused BASE is refused before spawning another supervisor.

Invalid options (a BASE that does not resolve under `/tmp/agent-offload`, no peers, non-positive budgets, a forced lane not in the roster, a same-kind peer) are refused before any pane, model or launch marker exists. Inside that root any slug works (spaces, quotes, non-ASCII, nesting, a relative path or a symlink that resolves there), and peers always run in the fixed `.lanes/<pool>/<lane>` workspaces, so no BASE spelling reaches a trust or approval prompt. Other commands: `xcheck wait --base B [--timeout S]` (subscriber; reattaches without relaunch), `xcheck status --base B` (render from files), `xcheck activity --base B [--lane NAME] [--json]` (one compact line per lane; `--json` requests full metadata without peer findings), `xcheck cancel --base B [--lane NAME] --reason TEXT` (prevalidate all selected runner identities before signalling; preserve the operator’s reason in final status). Caller or supervisor interruption detaches; it never cancels peers.

Exit codes: 0 every lane settled (read the table); 2 refused before any spend; 3 `wait` timed out while lanes run; 130 supervisor interrupted.

`xcheck models` reads provider-owned sources on every invocation. OpenCode’s advisory client metadata comes from the V2 native catalog, which uses its bundled/cache snapshot and performs TTL-based background refresh; this call does not force a synchronous Models.dev refresh. Provider prices and served IDs are still fetched live, so stale advisory metadata can leave a new free offer needing client setup but cannot establish its price. [OpenRouter's live model API](https://openrouter.ai/api/v1/models) reports prices, modalities and tool support. Zen's [live model list](https://opencode.ai/inference/v1/models) reports IDs only, so those IDs are joined to the endpoint and pricing tables of its console docs. The [deployed docs page](https://opencode.ai/v2/docs/console/models/) serves HTML tables, read with the standard-library HTML parser. No source branch, markdown fallback, login, browser or inference is used by discovery. Tables with ambiguous headers, duplicate identities, merged cells, incomplete rows or missing charge columns fail closed. The live-list join omits documented models that are not served. A documented free model absent from the live list is omitted; System One decision models are excluded. Cerebras' [public pricing API](https://inference-docs.cerebras.ai/api-reference/models/public-models) is checked too; trial credits are not treated as standing free models, and only offers with all reported charges known and zero can qualify. Every reported price component must be known and zero. Both discovery formats require tools, text among their input modalities and text-only output. Additional image, audio or video inputs do not disqualify a coding model; image/audio/video-only inputs and non-text outputs are excluded. Offers with an announced end date are also excluded as promotions rather than standing free tiers. A failed source omits that provider and reports the gap; there is no stale pricing fallback.

```bash
xcheck models                              # current provider-confirmed zero-price offers
xcheck models --provider openrouter --json # sources, exact selectors, client support and account variables
xcheck models --provider opencode          # Zen's live availability + current documented pricing
xcheck models --sources /path/sources.json # extend provider discovery without maintaining model IDs
```

`--provider` is repeatable and selects a discovery source; unknown sources are refused. `--limit` defaults to 20; undated offers appear first so newly published models are not hidden by lagging dates, then dated offers sort newest first. OpenCode's native `model.list` API supplies local client support and, for Zen, tool capabilities and advisory release dates. Its Models.dev prices and deprecation markers do not establish provider availability or price. New provider models missing from the client listing remain visible as `needs-client-setup`. A ready model prints `--add` when it is in neither `OPT_IN` nor `DEFERRED`, `pinned` or `deferred` when it is. Separately from those marks, each queried provider's read is `ok`, `failed`, or `empty` over its pre-filter rows — the documented exact served ids and their price state, before endpoint/client capability filters and `--limit`. Zen also reports `served_ids` from the raw live inventory, so an undocumented live id is distinguishable from a vanished one. A pin's verdict reads only its own provider's read: `free` while the exact id is served at zero price (client `tools: false`, missing metadata, or `needs-client-setup` never change that), `gone` only when the read is `ok` and the exact id is absent from the live inventory or parsed at a price above zero, and `unknown` when the read failed, joined to no rows, was never queried, or served the id with a price that did not parse. `missing` prints only for a `gone` pin; an `unknown` provider prints none. Marks and verdicts are computed on the full result, before `--limit`. A locally deprecated model is also marked for client setup. OpenRouter creation dates come from its API; Zen's API generates a timestamp for every request, so those timestamps are never treated as model release dates. Sources, per-provider reads, per-pin verdicts and date provenance are included in JSON. Explicit `opencode/<model>` and unprefixed Zen lanes of one model share one pool.

A sources file maps provider IDs to definitions and adds to or overrides the built-ins. Example: `{"vendor":{"format":"priced-json","models_url":"https://vendor.example/models","docs_url":"https://vendor.example/docs","auth_env":["VENDOR_API_KEY"]}}`. URLs must be public HTTPS without credentials; `auth_env` holds informational setup names only and does not change lane credentials; connect added providers through OpenCode’s stored auth or provider configuration. The lane environment retains only the existing explicitly permitted provider keys, not arbitrary keys declared by a discovery source. `priced-json` accepts a `data` array with `id`, `pricing.prompt/completion` and any other charges, text input/output modalities (under `architecture` or at top level), and `tools` under `supported_parameters` or `supported_features`. Optional `created` is an epoch release date, `expiration_date` an ISO date, and `deprecated`/router metadata exclude those models. The `zen` format reads deployed HTML endpoint/pricing tables. Other response formats need a focused adapter; unverified providers are never offered based on a third-party zero price.

**The free roster refresh** (`~/git-projects/xcheck-free-models`, launchd, once per Europe/Lisbon date at the first wake from 06:30; runbook in its README). It runs `xcheck models --json` for Zen and OpenRouter. Onboarding is one passing check. Then one real headless `xcheck run` (`--orch other --web packet --cap 900`) launches every candidate as a lane on a one-file packet. A candidate is a listed, client-ready offer not yet in the roster: any Zen offer, the tracked OpenRouter Nemotron lane, or a lane an earlier refresh saw. Only lanes the same refresh priced at exactly zero are launched, and a candidate that does not end `done` is checked once more in the same refresh. A candidate that ends `done` joins the roster file, written atomically. One that does not is checked again every morning until it passes. Members are not retested: a member stays while its provider lists it at zero price, and leaves only when an `ok` read of that provider no longer does. A failed or empty provider read removes nothing. The last seven check BASEs stay under `/tmp/agent-offload/xcheck-free-models/`. A failed refresh (Zen read not `ok`, discovery unavailable, a lane-check run that cannot complete, or every lane failing) keeps the last good file and retries hourly. Mail is failure-only, one `[XCHECK-MODELS] [MONITOR FAILURE]` per Lisbon date, and the Healthchecks check `xcheck-free-models` covers a job that stops. Roster churn is logged in that project's `logs/refresh.log`, never mailed. `xcheck models` marks a ready row `pinned` when it is in the roster and `--add` until the next refresh adds it; `doctor` prints `new` for the latter and fails on a `gone` roster lane until the next refresh drops it.

Roster membership certifies access and a tool-using answer, not review quality. Select general or coding models for a plausible review role; prefer the Zen endpoint over an OpenRouter duplicate. A model's opaque name, missing size or recent release is not evidence of unsuitability. Domain specialization, correlated family coverage and measured review quality inform task selection; they do not establish price or availability.

`adapters.DEFERRED` stays available for an operator decision to hold a passing offer out of routine use; it records an observed run outcome, never an inferred permanent defect. An endpoint error, silence, operator cancellation or malformed final answer alone does not establish model unsuitability; the next refresh checks the model again.

Zero token prices do not establish account readiness or review reliability; some trial or Contributor offers permit logging or training. `xcheck models` itself performs no inference, config edit or roster change; the refresh is the only writer of the free roster, and nothing substitutes one model for another. Each discovery or lane-check result is an observation for that day, not a guarantee for a later run.

Gemini Flash is the ratifying lane: it tends to agree with the packet's claims, false ones included. Assess its findings against the evidence. `done` certifies the output contract, not review quality. Same-family lanes (two lanes of one model family in a roster) are correlated. Returns diminish after about three strong, independent peers; add a lane for a distinct capability or failure hypothesis, not for volume. The roster is fixed at launch; add a reviewer in a fresh BASE.

## Routine review planning and qualification

A routine code review uses Codex, Claude, Grok and Gemini Flash, excluding its orchestrator. No Pro lane is currently required; introduce a future replacement separately after verification. Add Devin explicitly when another independent code reviewer is wanted and its selected offer and access are verified. It has no quota meter, so it remains opt-in. Keep all supported adapters and the free roster available; routine roster membership is a review-quality decision, separate from endpoint availability. Preserve each selected model's pinned/default effort; do not lower it to repair output formatting.

Run the required suite once on the capable host and stage its exact command, result and environment limitations with the complete source. Peers review the focused delta and relevant contracts, with the whole tree available. A peer may run a targeted reproduction for a concrete finding. It must not repeatedly run the full suite, repair its sandbox, or edit the reviewed implementation. An environment-blocked check is a limitation, not a code defect; record it and finish the review. A comprehensive scope is an explicit task choice, not a reason to keep investigating after the requested evidence is established.

A qualification records four separate outcomes: endpoint/tool access, native final-answer completion, output-contract compliance, and useful verified review evidence with elapsed time. Preserve the packet, exact selector/effort, harness versions/settings, raw stream, exit and operator interventions under its BASE so the outcome can be re-examined. Before attributing failure to a model, check packet completeness/provenance/scope, prompt clarity, routing and permissions, native tool results, transport/completion events, and result capture; replay a settled stream through the reader when capture is in doubt. A tool completed before silence does not locate the later stall. If evidence cannot distinguish the model, provider or harness, record the cause as unknown. A fresh task should distinguish a stated hypothesis or supply missing useful-review evidence; change one relevant condition where practical, and report confounders when several changed. Do not infer a cause from a successful rerun alone. A smoke proves access and framing, not suitability for a large audit. Auth, capacity, HTTP 429/503 and a failed inventory read are temporary access states unless successful provider evidence establishes otherwise. A model is absent only after a successful inventory check omits its exact selector. Repeated wrong findings or excessive cost relative to added evidence affect routine roster membership; they do not justify deleting a working adapter. Silence is pending unless an explicit owner limit or cancellation settles it.

Report a malformed completed answer as invalid and adjudicate its concrete claims as leads. Do not rerun a complete code audit solely to replace a missing newline or marker. Fix the schema instructions for the next task: show the exact two-line proof/marker ending and require a final assistant message after all tools. Never promote a draft or reasoning-only turn, normalize findings, or erase the original stream/status. Only relaunch when a changed task or repaired launch condition can provide evidence that is actually missing.

The owner chose no automatic routine timeout. After one hour the supervisor prints one diagnostic warning with pending lanes, runner liveness, queue/running phase, stream event/tool counts and native tool state where available. This warning never settles or cancels a lane, and changed metadata never proves useful progress. Use it to investigate locks, blocked tools and repeated verification. An explicitly requested --cap remains available and separately bounds pool admission and spend; native inventory subprocesses have their own bounded reads; without an explicit cap there is no overall startup deadline. No cap is inferred from silence. Slow optional models should not be selected routinely merely because their token price is zero. Do not start another subscription/free-model round to ratify deterministic repairs that already have failing-before/passing-after regressions.

## Packet

```text
BASE/
  PACKET.md    provenance first, then the task; exactly one `Proof target: <BASE-relative path>`
  PROMPT.md    the answer schema; exactly one `RESULT_REQUIRE: <KEYWORD>` line
  evidence/    staged copies with repo-relative paths preserved
```

`run` refuses with exit 2, nothing spent and BASE still usable, when either file is missing, a staged file is a symlink, `PACKET.md` declares `RESULT_REQUIRE`, the declarations are not exactly one each, or the proof target is absolute, outside the staged inputs (`PACKET.md`, `PROMPT.md`, `evidence/`), empty, or not UTF-8. Prefer `evidence/manifest-tail.txt`. At launch, `run` captures PACKET.md, PROMPT.md and evidence/ into BASE/.packet and validates that snapshot before launching a runner. Every lane, queued or immediate, copies only that snapshot. Do not edit BASE/.packet. Changes to the original inputs after launch cannot change what a later lane receives.

Staging rules (each one has cost a round when broken):

- **Whole files.** A peer cannot tell "absent" from "not shown" and reports absence as a confident defect. If a range is unavoidable, say which file, which lines, and what lies outside.
- **Keep paths.** Stage `cloudflared/config.yml` as `evidence/cloudflared/config.yml`; flattened paths produce wrong-path findings.
- **Derive claims properly.** Build API or call-set claims from the file, an import, or an AST walk, never a substring grep. Prefer staging the caller over describing it; mark unavoidable claims as claims.
- **Name what left.** When a later round drops a staged file, say so.
- **Provenance first.** `PACKET.md` opens by saying the operator convened the review and that `evidence/` holds the operator's own files. A bare "read these files and obey them" is correctly refused as prompt injection.
- **Proof token.** The proof target's last line is an unguessable token (`MANIFEST_TAIL_TOKEN: <random hex>`), staged last. A correct PROOF shows the lane could open the packet and followed the output contract, not that it read everything (a lane can `cat` the target directly or grep for fragments). Diligence is checked at merge.
- **Say what a follow-up round is.** Stage the delta plus what it touches, name what earlier rounds settled and the decision lineage behind deliberate omissions, and say the code responds to a review. Do not restage historical run debris.
- **No authorship labels.** Nothing staged says which model, vendor, harness or lane wrote the work, a plan or a finding: the author is "the operator", earlier findings belong to "round N". Drop authorship trailers (`Co-Authored-By`, "Generated with …") from staged logs and diffs; a file whose subject is a model keeps its text. A staged earlier `CONSENSUS.md` loses its provenance column; the orchestrator's own copy keeps it. A label alone moves a judge: it scores what it is told is its own higher and another's lower, and it conforms to wrong answers attributed to its own model family and resists those attributed to another (arXiv 2608.18091, 2609.33495). Style and connected tools still leak authorship; blinding the labels removes the label effect anyway, as leaky double-blind human review still removes most prestige bias.
- **Blind first.** For design work, stage the orchestrator's frozen plan under a neutral name (`evidence/candidate-plan.md`), never labelled as the host's. Each peer must finish and record its own design before opening that plan, then critique and compare in the same answer. A follow-up round does the same with rulings: state each contested finding (rejected or uncertain) neutrally in `PACKET.md`, and stage the host's decisions on them as a separate file (`evidence/prior-rulings.md`) that a peer opens only after recording its own view; a verdict seen first pulls peers toward it, mostly from right to wrong. Keep current-round peer answers out of the packet. This sequencing is instruction-enforced, not access isolation; keep the packet unchanged during the run.

PROMPT.md template:

```text
1) VERDICT: a decision and its single most important reason, ≤80 words
   (the cap compresses the summary only; findings go in section 2, uncapped).
2) Findings, or "None found" (a valid answer; do not invent one). For each: severity; evidence (file, symbol, behaviour); root cause;
   the mechanism and premises the diagnosis rests on; how often the scenario
   occurs and what ignoring it costs; the smallest repair (code or pseudodiff
   when the evidence allows); what must stay true; a verification that fails
   while the defect is present; confidence and missing context.
3) What you would delete from the target, and why deleting it is safe.
4) Alternatives worth considering (if any).
5) One-line recommendation.
6) PROOF: <the last non-empty line of the proof target, copied exactly>
   Keep this on ONE plain line, without fences or annotations; put a real newline before the marker.

The next line is packet metadata; do not include it in your answer.
RESULT_REQUIRE: VERDICT
The final two lines must be separate, plain lines. Example:
6) PROOF: MANIFEST_TAIL_TOKEN: <actual token>
RESULT_COMPLETE
Final line, alone: RESULT_COMPLETE
If you cannot do the review, make the final line RESULT_INVALID instead.
```

The markers are literal lines: no period, code fence, quote or explanation after `RESULT_COMPLETE` / `RESULT_INVALID`. PROOF is `6) PROOF: <token>`, or a bare `6) PROOF` heading followed by the token alone or by a `PROOF: <token>` line (bold, bullets or backticks around either are fine); anything else after `PROOF:` is compared as the token and fails, and so does pasting the whole proof file. The last PROOF line decides, so findings may quote PROOF lines. An answer also needs review text beyond the heading, PROOF and marker. `tests/test_laws.py` states the whole grammar as properties.

**What every lane is told** (`run.MESSAGE`): the owner convened the review; read `PACKET.md` then `PROMPT.md` (PROMPT decides format); work from the staged directory; connected MCP tools are available, external actions (sending messages, changing records) are not; nobody answers questions mid-review. Codex, Claude and Agy use tools that read (plus web in live mode); Grok, OpenCode and Devin may also run Bash and write disposable scratch inside their own workspace, never the staged files. Every lane prints the answer as its final message; only native turn completion publishes it, so a complete-looking draft is not a publication signal.

**What `run` adds to BASE**: `run.json` (roster, contract and settings fixed at launch; Herdr pane ids added as panes are created), `lanes/<lane>/` (`message.txt`, `staged` stamp, `pids.json`, `exit.json`, `stream.jsonl` + `view.log`, `stderr.log`, `harness.log` where the CLI supports one), `RESULT-<lane>.md` (the captured answer), `STATUS.json` / `STATUS.md` (one row per selected lane, skipped ones included). Peers work in stable workspaces `/tmp/agent-offload/.lanes/<pool>/<lane>/`, restaged only after pool admission and reused by the next run of that lane. The pool namespace makes different pools disjoint even when selectors normalize to the same lane name; inspect a run's evidence in its BASE, not in a later run's workspace. Artifacts stay in `/tmp`; never copy run directories into the vault.

## Lane statuses

| Status | Meaning | Orchestrator action |
|---|---|---|
| `done` | answer ends `RESULT_COMPLETE`, has the required heading and review text, PROOF matches; policy diagnostics are separate | read, report diagnostics and adjudicate |
| `invalid` | an answer exists but breaks the contract (reason names how), or the peer declared `RESULT_INVALID` | read it anyway; its findings are leads; tell the operator |
| `failed` | no answer; reason is the harness's structured error, else its first stderr line | read `reason` + `stderr_tail`; tell the operator cause and remedy |
| `timeout` | idle limit, `--cap`, or the runner's own bound ended it | tell the operator; partial output is in `stream.jsonl` and any draft in `RESULT-<lane>.md` |
| `skipped` | no review inference: capacity reserve, auth, unknown capacity, startup/inventory unavailable, exact model absent, or pool busy past `--cap` | tell the operator; `--force-lane` only on their say-so |
| `interrupted` | a lane runner was signalled or explicitly cancelled | the final reason preserves an explicit cancellation reason; a signalled subscriber/supervisor only detaches |

Never relaunch a lane that died of quota or auth in the same run. A lane lost to a bad packet or prompt is rerun in a fresh BASE after fixing the packet, and the operator is told. A lane that dies within seconds with a usage message usually means a flag drifted: read the first stderr line, run `xcheck doctor`, and compare the installed CLI's `--help` before blaming quota or the model. The only answer channel is the lane's final message; a review written to a file instead ends `failed` and is not scouted. Read its saved stream, and the file in `/tmp/agent-offload/.lanes/<pool>/<lane>/`, before the next run of that lane restages it.

## Placement and views

**Headless**: `run` starts a detached supervisor; the caller is a subscriber. Each lane runner owns its own process session. Losing or interrupting the subscriber/supervisor leaves lanes intact. Reattach with `wait`; only `cancel` intentionally stops a live lane. It also settles a lane whose runner already exited (as `wait` would) or never started, so one such lane does not block cancelling the rest.

**Herdr**: chosen only when the operator's `~/.agents/bin/herdr-caller-context` returns exit 0 with a `verified` binding (pane, session, socket and live terminal identity) and that pane's readable layout is at least 176×14. Title fragments, focused panes and inherited `HERDR_ENV=1` never establish caller identity. A Grok orchestrator verifies when its `GROK_SESSION_ID` equals the session id on Herdr's grok agent record for that pane. The operator stated that this match is a verified Herdr pane: the sandboxed tool subprocess inherits the id and is not in the pane process list, and the record already names the pane and terminal. All placement operations target the verifier's exact socket and session, even if inherited context disagrees. A missing helper, unconfirmed/ambiguous context, incomplete binding or unreadable layout gives headless in auto mode; explicit Herdr mode refuses and names the observed blocker (the helper state, an incomplete binding, the measured layout area, or the layout call's error). Re-verify with `python3 -c 'from xcheck import herdr; print(herdr.caller())'` in a real caller and the ownership tests. The first lane splits right of the orchestrator (`--ratio 0.62`: the orchestrator keeps 62%); the rest split that column into equal rows in roster order, titled `xcheck:<lane>`. Lane panes are addressed only by the ids their split returned, never by title or focus, and never by `--current`. Each pane runs `exec <lane runner>`, so the pane is the runner: Herdr closes it when the runner exits, three seconds after its final line. Nothing closes panes by id. If the supervisor dies, panes finish on their own and `wait` reattaches.

**The pane**: a Herdr pane and headless `view.log` show the same display of stream events the runner has already parsed. The header names the lane, model, effort, pid and start time; the launch argv is not on that screen. Each tool is one line with its key argument (path, query, URL, command, or `server.tool`) and ✓ or ✗ when the stream reports the outcome. Thought and message text are wrapped paragraphs; long thought is trimmed, and file contents and search results are not printed. ANSI styling is used only when stdout is a terminal, so `view.log` stays plain. After the final status line the pane names `RESULT-<lane>.md`, and prints the answer's opening lines when that text was not already shown. The pane is not a completion signal.

**The stream**: one runner reads each lane's structured stream, and only that harness's native turn completion ends the review. Codex (`codex exec --json`): the answer is the last `agent_message` after the last tool item, `turn.completed` ends the turn and `turn.failed` fails it. Claude (`claude -p --output-format stream-json`): the `result` event ends the turn and carries the answer; `is_error: true` makes it a failure. Grok, Agy, Devin and OpenCode run acpx `--format json exec` and the runner reads the ACP JSON-RPC stream: the answer is the agent text after the last tool call, and the response to acpx's `session/prompt` with `stopReason=end_turn` ends the turn; any other stop reason (`cancelled`, `max_tokens`, `max_turn_requests`, `refusal`, unknown) fails. A process exit without completion fails and retains any captured text as a diagnostic draft (Claude's text arrives only with its result, so a Claude lane that exits early keeps none); intermediate messages and completed tools never settle a lane. Validate the captured final answer before calling it usable. Stdout resets an explicitly requested idle clock; stderr does not. Once the harness exits, the runner reads its stdout until 3 s of silence (`DRAIN`; completion is always written before exit) and then ends the group, so a descendant holding that stdout cannot keep the lane pending.

For the ACP lanes: acpx prints both directions without saying which, and JSON-RPC ids belong to the side that sent the request, so an agent request can reuse acpx's own ids (Agy's `session/request_permission` took id 0, acpx's `initialize` id). The reader therefore never assumes one id space. Only a `session/prompt` response carries `stopReason` (ACP schema), so that shape settles the turn whatever id it reuses. The first `session/prompt` request is acpx's (it sends one, `--prompt-retries 0`, and the method is client-to-agent); a later one is counted like any other request. Every other request id, from either side, is counted until answered; a sender reuses an id only after its earlier request at that id is answered. An error carrying the prompt's id while another request with that id is open is held: the other response at that id says which side sent it, and if acpx exits first (acpx, the client, does know the direction, and exits non-zero after a failed prompt) the held error is the failure; a new request at that id instead proves the held error answered the earlier request at it. Errors answering other requests, and acpx's own id-null errors (agent disconnected, `--model` refused), are kept as the reason only if the turn never completes. `tests/test_xcheck.py` `AcpCorrelation` holds both collision orders.

A native prompt error ends a lane as `failed`, even if its process keeps emitting retry events. A Codex `error` event (a reconnect notice) can recover, while `turn.failed` is terminal. OpenCode native upstream rate limits are excluded under the operator’s stated policy even if retrying. Quoted error text in a review is not a native error. Report the cause and exclude that lane from usable review coverage.

A timed-out, interrupted or failed lane retains that status even if it printed a complete-looking draft; an explicitly requested cap is checked before completion, and a partial answer never overrides the termination reason.

Completion is always the lane's `exit.json`, never pane text.

## Capacity

Each pool has one free meter that runs no inference, read by `xcheck/capacity.py`: Codex `app-server` `account/rateLimits/read` (5 h and weekly windows), Claude's OAuth usage endpoint with the keychain token (its `limits[]` list: session, weekly, and a weekly cap scoped to the lane's model family, where a scoped cap it cannot attribute counts; the flat `five_hour`/`seven_day` keys only when `limits[]` is absent), Grok's credits meter (the worse of the account and Grok Build usage percents on the CLI credits view; when that view has no percent, the same token's `GetGrokCreditsConfig` used-percent), and Agy's `agy -p /usage` (zero turns; the lane family's 5 h and weekly buckets). `xcheck capacity [--lanes …]` prints the readings with the same reserves `run` would apply. Each lane reads its own pool after admission and immediately before spending, so the reading is not stale and, in Herdr, runs outside any orchestrator sandbox. A lane spends only on `eligible`: the tightest window must have more than the reserve left, 10%, or `5 + 5n`% for the run's `n` lanes in one Agy family (capped at 90). The reserve protects the operator's interactive quota, which a runtime quota error arrives too late to protect. A meter that cannot be read is `capacity-unknown` and a rejected login is `auth-required`; with `reserve-low` they end the lane `skipped`. There is no fallback meter.

- Agy's `/usage` is served by its persistent headless `language_server`; a launchd agent keeps one running. Agy lanes spend through Antigravity's ACP server, which signs in with the same OAuth client as `agy` (`1071006060591`, found in its sign-in URL); the Gemini meter moved during an ACP review turn, so the meter and the lane share the pool.
- Claude `security` exit 36 is a locked login keychain (for example, from a remote session): run `keychain-unlock-gui` with the operator at the screen. Never `security unlock-keychain` from an agent shell: control returns before a password can be typed. `security show-keychain-info ~/Library/Keychains/login.keychain-db` checks the state without prompting. Otherwise pass a fresh reading from Claude Code's `/usage`, the lowest window shown, as `XCHECK_CLAUDE_REMAINING=<percent left>` and `XCHECK_CLAUDE_REMAINING_AT=<ISO time>` (at most 5 min old) in the environment the runner inherits, i.e. headless placement; it overrides the keychain, so unset both right after that one launch. Exit 44 means no login.
- The Claude meter checks the keychain token's millisecond `expiresAt` before HTTP, including a 60 s margin for the probe and clock skew. An expired or near-expiry token returns `auth-required`. The caller should make one supported non-inference refresh attempt: `env -u ANTHROPIC_API_KEY claude --safe-mode --no-session-persistence --tools "" --permission-prompts none -p /status`, then recheck `xcheck capacity --lanes claude:claude-opus-5-5:high`. Bound this startup probe to 55 s, remove any inherited nested-Claude identity variables, and verify the CLI still handles the recognized `/status` locally after upgrades. In Claude 2.1.287 print mode the command returns a local unavailable-headless message with no model query; startup still attempts native refresh. Exit 0 alone is not recovery: the capacity recheck decides. This uses native subscription auth with customizations disabled; it is not a review or a lane retry. If eligible, include Claude in a fresh BASE. If native refresh still fails or requires browser login/keychain unlock, report the specific blocker and ask the operator; use `env -u ANTHROPIC_API_KEY claude auth login --claudeai` only for that requested interactive sign-in. Never force an auth refusal, log out a working session, hand-roll refresh, or switch to API billing. `claude auth status` can still say logged in while the token is expired, and Anthropic can return 429 for that expired token. Malformed present expiry fails closed; missing expiry preserves the existing read path. No custom token refresh or fallback meter is used.
- The Claude usage endpoint also returns HTTP 429 when polled too often (CodexBar reads it too). The meter accepts positive finite `Retry-After` seconds or an HTTP date, otherwise 2, 4, 8, 16 s; zero/negative/nonfinite delays cannot spin. Requests and sleeps share a 30 s probe budget, with at most five requests, and then fail closed as `capacity-unknown`. A long throttle reports its delay and recheck remedy. Recheck with `xcheck capacity --lanes claude:claude-opus-5-5:high`; once it reads `eligible`, add the lane in a fresh BASE. `--force-lane` does not apply here: a launched BASE refuses a second `run`.
- A rejected Grok token may only be stale: running `grok` once refreshes it. The CLI credits view (`/v1/billing?format=credits`) can return the weekly period and balance fields without `creditUsagePercent` or a GrokBuild `usagePercent`. Balances, including zeros, are not a quota. That view omits the percent even while usage is above zero, so its silence is not a reading. When it has no usage percent, the same token reads `GetGrokCreditsConfig` on `grok.com`, the credits config behind `/usage`. The meter decodes that message the way grok.com's `/usage` code does: a unified-billing config (`isUnifiedBillingUser`, field 11, true) with no `creditUsagePercent` (field 1) has used 0%. Proto3 omits a zero float, and every observed percent is a whole number, so a week's usage below 1% arrives with no field. This is the normal state after each weekly reset; observed 2026-10-16 from the reset through two xhigh turns and a chat message. Otherwise used is the worse of field 1 and each product-usage percent (field 7), and `left = 100 − used`. A frame or nested message that is not clean protobuf, a missing or non-unified config, more than one data frame, or a percent outside 0..100 supplies nothing, and the meter stays `capacity-unknown`. Do not infer admission from balances. Re-read the web client's `/usage` decoding if the config's shape changes.
- A reading is a snapshot. A healthy Agy family can still hit a per-model cap ("Individual quota reached"); that lane fails with the harness's own error and is not retried.

## Locking and liveness

A quota pool (codex, claude, grok, agy-gemini; for OpenCode, which has no meter, one pool per Zen model and one per other provider) is spent by one run at a time, for two reasons: a capacity reading means something only while no other run draws on that meter, and the stable workspace and immutable snapshot need one owner per lane name, which needs a single owner. Lanes of the same run share their pool; disjoint pools run in parallel. Under `/tmp/agent-offload/.pools/<pool>/`:

- `gate`: exclusive, held for an instant while one lane decides admission. `busy`: shared by the owning run's live lanes; only a gate holder takes it exclusively, and it converts to shared while still holding the gate. `owner`: the BASE that last took the pool; it says who may join an occupied pool and is not liveness evidence.
- A lane takes only its own pool, then reads capacity, stages its workspace and launches; it never waits for a second pool while holding one. Waiting for the gate and for `busy` share one deadline (`--cap`) and happen in the runner, without model calls.
- The harness inherits the `busy` descriptor, so a killed runner's orphan can spend only while the pool stays held, and the pool frees when the last holder exits. acpx gives the agent it starts only stdin, stdout and stderr, so an ACP lane's agent command starts with `xcheck hold`: under `gate` it joins only a pool that is still busy and owned by this BASE, exits 75 otherwise, and execs the server holding its own shared lock. The server then holds the pool exactly as a native harness does, even if acpx is killed alone. The runner covers spawn and setup with unconditional cleanup using the actual owned child, including a failed pids.json write. Cancellation signals are deferred while establishing ownership and settling the group; the child restores the inherited signal mask before exec. The whole group is settled before admission is released.
- Never delete or replace a lock file: a new pathname is a different lock. All runs share the host-local root; `XCHECK_ROOT` exists for test isolation, not to bypass contention. The locks coordinate cooperating runs; they are not a security boundary.
- A descendant that leaves the process group and outlives both runner and harness is out of scope: nothing in scope spends quota that way. If it kept the inherited descriptor, later runs on that pool remain queued (or end `skipped` under an explicit cap); find the holder with `lsof +D /tmp/agent-offload/.pools`.

Runner and supervisor liveness is an exclusive lock on their own `alive` file, released by the kernel on crash: no PIDs, no process table (a sandboxed Codex orchestrator may be denied `ps`). `pids.json` and `supervisor.pid` exist for diagnosis. `BASE/.launched` (atomic mkdir, created after every refusal check) makes a BASE launch once; `wait` reattaches and never relaunches. Every settled runner writes `exit.json` exactly once. A requested cap arms a kernel alarm at `2·cap + 300` s; the default has no elapsed-time alarm. Unknown startup remains pending rather than becoming a guessed failure after 90 s. A runner that dies without `exit.json` is settled by `wait`: it stops the orphaned harness only after `ps` confirms the command line names that lane's directory or workspace, never on a PID alone, and keeps existing output for diagnosis. Recovery (`wait` after a runner died, or a runner's own exception handler) replays the saved `stream.jsonl` through the same reader: an answer is usable only if that stream holds native completion without a native error; a complete-looking RESULT file alone cannot promote a draft. It rechecks exit.json after a liveness probe so an authoritative record published during the probe is preserved. OpenCode’s acpx argv names its workspace with `--cwd <work>`.

## Harness facts

`xcheck doctor` checks that every flag the adapters use appears in the installed CLI's `--help` (acpx included), the Grok/Devin/OpenCode model pins, the Agy pins against the ACP server's advertised ids, and the Agy preflight: acpx on PATH, the ACP server installed (its `VERSION`), no lane-changing keys in `~/.acpx/config.json`, and the server's Keychain login. **Agy** runs only through Antigravity's ACP server (`agy_acp_server.par` + `localharness_external`, the headless form Google ships for IDEs), driven by acpx, in both placements. `agy -p` ends the whole turn the moment it soft-denies a tool; the ACP server does not. Re-verify with a lane that runs `touch` outside its workspace: `Operation not permitted`. Network stays open, so packet-mode web limits remain instructions. `GEMINI_HOME` is the lane's `gemini-home`: `antigravity-acp/settings.json` with `auth.type=oauth-personal` and `config/mcp_config.json` holding Claude's review servers in the server's shape (HTTP as `url`; it ignores `serverUrl` and `disabled`), minus `fff` (rejects the `server/discover` probe and fails the whole turn) and `qmd` (never finishes connecting over HTTP, and the server waits for every server). A server MCP failure arrives as a single-line whole answer `The MCP server '<name>' failed to initialize…` on a turn that ends `end_turn`; the reader fails the lane with that line; a review quoting it across multiple lines remains review text. A fixed-choice question to the user ends the turn (acpx exit 5) with no completion, so the lane fails. Neither `agy update` nor acpx updates the server: `~/.local/bin/agy-acp-server-update` (topgrade custom command, chezmoi-managed) follows the official ACP registry, swaps both files together and refuses binaries not signed by Google's Team ID `EQHXZ8M8AV`. acpx is a global npm package updated by topgrade's npm step; npm needs `fsevents` in the user `allow-scripts` list for that.

**OpenCode** (2.0.27) runs through its native ACP server and acpx, in both placements. The ACP server remains owned by the lane rather than the shared background service, preserving cancellation and pool custody. Here `opencode` is whatever the lane's PATH resolves first (an operator sandbox wrapper only if it wins on PATH). No added permission rules, custom reviewer agent or config overlay: the stock `build` mode and existing user MCP/provider configuration remain. The former `--auto` approval behavior is carried by acpx `--approve-all`; `--no-terminal --no-fs` disables client-side tools, `--auth-policy skip` preserves stored login, and `--prompt-retries 0` prevents client retries. Web and packet-mode limits remain instructions. The native server has no OS sandbox of its own, and xcheck adds none. The operator’s wrapper uses the published `@anthropic-ai/sandbox-runtime` with project/state write roots and a specific `com.apple.FSEvents` grant for recursive config and skill reload. The shared user service is disabled because its sandbox would otherwise inherit its first launch directory, and the wrapper protects `service.json` against agent writes. An explicit effort is applied after model selection with `exec --config-option effort=<variant>`. It must be advertised by that model, otherwise startup fails before a prompt rather than downgrading. A failed listing, or a model absent from it, ends the lane `skipped` (`startup-unavailable`) before spend. Both placements support explicit effort. No model substitution is enabled.

Free Zen offers have refused custom permission/tool sets with `FreeTierError`, so ACP does not add any.

OpenCode’s terminal provider errors include `data.service=session`; a matching prompt error fails immediately even if later retry events continue. Its ACP event bridge does not expose intermediate native retry status; the native server can retry internally before its final error, as the previous `run` command did. `activity` retains the ACP session id so the existing workspace- and time-checked native store probe reads `session_v2` and assistant `session_message.content` and still reports tool/reasoning metadata. V1-only `session`/`part` rows cannot identify a new V2 lane.

**Herdr** (0.9.3). `pane list` gives each pane's `pane_id` and `terminal_title_stripped`; `pane layout --pane <id>` gives tab size; `pane split --pane <id> --direction right|down --ratio <share kept> --cwd <dir> --no-focus` returns `.result.pane.pane_id`; `pane run <id> <command>` types into the pane's shell (typeahead is buffered, so no readiness wait is needed); a pane closes when its process exits.

A peer that inherits them becomes a nested session of the orchestrator, runs at its effort, or can drive the operator's Herdr. Removing `HERDR_*` alone does not stop that: the `herdr` CLI falls back to its default socket, so the runner sets `HERDR_SOCKET_PATH` to a path that cannot exist and every `herdr` call in a lane finds no server. Codex and Devin run each shell command through the operator's zsh rc files, which would load keychain secrets into the environment; the runner sets a guard variable those rc files honour to skip the secret load, and any new secret loader must honour the same guard. Re-verify with a lane that counts API-key variable names without printing values: no key may remain except the selected OpenCode provider’s explicit allowlist. The runner removes them, every `CLAUDE*` name (the Claude adapter also reads `CLAUDE_CONFIG_DIR`, `CLAUDE_MODEL_CONFIG` and `CLAUDE_AGENT_*`), `MAX_THINKING_TOKENS`, `IS_SANDBOX`, every `ANTHROPIC_*`, `GROK_SANDBOX` and the redirecting `GROK_*` names, `OLDPWD`, every `ACPX_*` (acpx promotes `ACPX_AUTH_<X>` to `<X>` in the agent's environment), and every `*_API_KEY` except the provider key an opencode `provider/model` lane needs (`ZAI_API_KEY`, `OPENROUTER_API_KEY`), and sets `PWD` to the lane workspace: opencode roots its file tools and shell at `PWD`, not at its real working directory, so an inherited `PWD` points it at the orchestrator's directory. Harmless preferences such as `GROK_TELEMETRY_*` pass through. Re-verify: `env` in the orchestrator's shell, then the fake-harness env test.

OpenCode metadata startup retries a returned non-zero exit up to three times, with one-second pauses under the existing serialization lock. A missing executable, denied execution or 60-second subprocess timeout is reported immediately rather than repeating the same failed boot. This is an inference-free metadata retry, not a reviewer-turn retry. The published V2 standalone server holds an stdin ownership lease and exits on EOF even if its CLI owner is killed; [upstream implementation](https://github.com/anomalyco/opencode/blob/v2.0.27/packages/cli/src/services/standalone.ts) and [owner-death regression](https://github.com/anomalyco/opencode/blob/v2.0.27/packages/cli/test/standalone.test.ts) cover this mechanism. Do not add another cleanup group without a demonstrated escape from that lease.

**Operator rules reach peers.** Codex lanes load `~/.codex/AGENTS.md`; Grok loads `~/.agents/rules` through `extra_rule_dirs` (a `GROK_CONFIG` overlay does not clear it). Codex keeps the operator’s `CODEX_HOME` so subscription credentials are not forked. Grok isolates `GROK_HOME` while `GROK_AUTH_PATH` references the original login and `extra_rule_dirs` references the canonical shared rules. The lane message states the review task directly and scopes those rules to it. Agy is the exception: its ACP login lives in the Keychain, so its lane `GEMINI_HOME` carries no operator rules at no auth cost. Re-verify with a scoped lane that quotes the global instructions it received, preserving its selected effort.

**Independence.** Local commands and MCP tools can read outside the workspace, including another lane's result. Separate copies and the instruction prevent deliberate sharing, not adversarial reading.

## Current limits

- Distinct model IDs can produce the same sanitised lane name; a roster with duplicate names is refused before launch. The exact ID remains in run metadata and argv. Across runs, colliding names under different pools have different workspaces; within one pool the existing lock owns the workspace. Empty, dot and parent path segments in model selectors are refused.
- Claude and Codex register only approved local/keyless MCP servers (Codex disables every other server it would load, plugins included, and any with a stored login), and Claude blocks account connectors; packet mode omits their remote MCP retrieval servers. Grok keeps its filtered lane config; Agy, Devin and OpenCode retain instruction-only MCP/web restrictions. Shells, connected local tools and native web tools prevent a general free-only network guarantee. `--web packet` is not a security boundary for untrusted material.
- Grok and Devin’s shell can write anywhere the operator can (Grok’s unrestricted profile is explicitly authorized; Devin’s sandbox hides the login), including another lane's scratch; their own-workspace limit is an instruction. OpenCode inherits the operator's sandbox wrapper when it wins PATH, as verified in the V2 smokes; xcheck adds no boundary if PATH resolves directly to the vendor binary. That wrapper allows shared `/tmp`/`TMPDIR`, so it does not isolate other lanes’ scratch or run records under `/tmp/agent-offload`. It also shares writable OpenCode config, database and MCP caches with other sessions; a lane can alter state those sessions read. The wrapper omits HOME and its ancestors as project write roots and keeps `service.json` read-only to preserve the disabled shared-service setting. Codex (read-only sandbox), Claude (no shell) and Agy (Seatbelt: workspace, lane home, Agy uv cache, Keychain) cannot.
- Agy lanes share `ROOT/.cache/agy-uv`, which every Agy lane may write, so one Agy lane could alter the uvx MCP packages another Agy lane runs. It never reaches the operator's uv cache.
- No Agy lane gets `fff` or `qmd`: the ACP server cannot start them (see Harness facts). Re-test after either server or the ACP server updates.
- Grok 1.0.46 and 1.0.49 refuse `read-only` startup on symlinked container-runtime endpoints such as OrbStack's `/var/run/docker.sock`. The operator chose unrestricted reviewer lanes so the running Docker integration stays intact. Do not remove the Docker alias or reintroduce that failing profile automatically.
- A turn that blocks silently (a native tool buffering output, a stuck login) remains pending unless the operator supplies `--cap`/`--idle` or cancels; silence is not evidence of inactivity.
- A Herdr failure after a split but before `pane run` leaves a pane with an idle shell; close it by hand. (A failed `exec` makes zsh exit, so that pane closes itself.) A placement failure known to the supervisor is settled explicitly. An unobserved runner startup remains pending; elapsed time does not prove it failed. `cancel` settles it: with no runner recorded it takes the lane's life lock (proof none runs) and writes `interrupted`; a runner that starts later finds that record under the lock and stops.
- Only an explicitly supplied `--cap` ends a lane on elapsed spend. It is a cancellation policy; rerun in a fresh BASE after recording lost work. Native session continuation cannot restore killed OS processes or deleted scratch.
- Blinding covers labels only. Style, the reasoning itself, and connected tools (pond session history, qmd over this vault) can still tell a peer who wrote something or how the host ruled.
- If a runner died and `ps` is unavailable, `wait` cannot confirm the orphan's identity and leaves it alone, noting that in the reason; its pool stays held until the orphan exits. Never kill a recorded PID on a guess.
- A full roster starts many MCP servers in the same second, which can exceed Keenable's 10 requests/s limit (HTTP 429); the lane that loses the race lacks that server for its session and keeps its built-in web tools.
- Claude lanes still read managed policy and `~/.claude.json` state. Grok lanes make one initial title-sampling call per session that no supported switch disables.
- `main` carries no locally patched dependency. The ACP forms of the Codex and Claude lanes, each with its local patch, are on the `acp/codex` and `acp/claude` branches; re-check their upstream trackers (Harness facts) at each upgrade.
- Captured fixtures cover live Codex exec answers, an unsupported-model failure and an exhausted 5 h window, Codex MCP tool calls (started, completed, failed), an Agy ACP turn with the server's reused request id, a Devin ACP shell/read turn, an OpenCode ACP shell/fetch/MCP/read turn, Grok missing quota percentages, live Claude stream-json answers and a model failure, and a real successful disallowed Claude Cloudflare call. Fixtures omit credentials, response headers and account identifiers. Deployed Zen price tables and the installed V2 progress-store DDL are captured as structural fixtures; they contain no account data. Other native account quota/auth failures still need captured fixtures; invalid-model fixtures prove parser shape only.

## ACPX boundary

acpx (OpenClaw's ACP client, npm, on the official ACP SDK) transports the Grok, Agy, Devin and OpenCode lanes, unpatched. Its exec path passes its environment through, keeps the agent in its process group, kills the agent's tree on SIGTERM/SIGINT/SIGHUP, and holds an inherited descriptor itself but gives the agent only stdio. `xcheck hold` restores the server's pool custody.

What stays in xcheck for every lane: quota admission and pool locks, immutable packet snapshots, launch-once, the proof contract, environment scrub, answer selection and validation. An ACP `end_turn` is not a review: the reader selects the final message and `validate.check` decides. All ACP lanes refuse lane-changing acpx config keys before admission and disable acpx's filesystem/terminal tools (client capabilities only; each agent's own tools follow its native policy).

ACP standardizes transport and completion: initialization, sessions, prompt updates, tool/permission requests and the prompt response. It does not standardize OS sandboxes, credentials or proprietary configuration, so vendor policy stays explicit per lane: Grok profile + version admission, Agy Seatbelt, Devin overlay + accept-edits, OpenCode stock build mode. Optional features are negotiated. See [ACP overview](https://agentclientprotocol.com/protocol/v1/overview). Codex and Claude read their first-party streams instead: their ACP forms need third-party adapters, and those adapters needed local patches (see their branches under Harness facts). Never use acpx's built-in Codex/Claude names: they resolve npm caret ranges at launch.

## Merge

1. Re-read `STATUS.json` and every `RESULT-*.md`, `invalid` ones included, right before merging. A truncated draft is a lead only; never manufacture a peer's final position from it.
2. Check each concrete claim's **premises** against the real tree before its reasoning. The ratifying lane fails at the premise: it can reject a correct fix because it misread code it was shown. Absence-of-code, wrong-path and packet-claim findings are packet suspects: open the real file first. A finding is rejected as wrong only on an observation that contradicts its premise or mechanism (a file and line, a run, a live read), never on argument; without one it is uncertain. The orchestrator usually wrote what is under review, so it is the one judge no label can blind, and it favours its own work most where it is unsure; this rule turns that unsureness into an uncertain row instead of a rejection. Out-of-scope findings follow the admission rule.
3. Never tally reviewers. Agreement counts only when premises were derived independently; same-family lanes are correlated. Volume is not quality, and a small delta is no reason to drop the expensive lane.
4. Judge each repair separately from its diagnosis: a correct diagnosis does not make its repair correct. The verification must be able to fail while the defect is present; two checks that read the same state are one signal. When no independent check exists, record the limitation or ask the operator to check; never claim completeness. For stored state, test that omission preserves the last value unless the contract explicitly calls for deletion. When comparing designs, a peer's preference for its own design is not evidence; take only the defects it names in the others. Compare on the requirements the frozen plan stated before launch, and apply a requirement learned from a peer to every design, the plan included.
5. Write `CONSENSUS.md`: one decision line; a confirmed / rejected / uncertain table with lane provenance; for each confirmed finding the selected repair, its verification, and why the host chose it when it differs from the peer's; lanes with no usable answer, never counted as disagreement. Uncertain is a finished ruling, not an undecided one: list every uncertain row for the operator in the next chat message. If no peer produced substantive evidence, say the review is unverified and why; relaunching an unchanged packet is not progress.
6. Verify every applied fix with a regression that fails on the defect. Use a fresh peer round only when an admitted finding or uncertain contract requires independent evidence that local checks cannot provide; scope it to the delta and the contracts it touches, with the decision lineage staged. Do not spend another subscription round merely to ratify completed deterministic repairs. Stop when no admitted finding remains.

**Admission rule.** A finding earns code only if its failure has happened or is likely within scope, and then it gets a tested repair. A real but out-of-scope finding earns one line in Current limits. Anything else is rejected in `CONSENSUS.md` with its reason. Ask reviewers what they would delete, not only whether something is correct. Never add prose to pre-empt a reviewer. Prefer fewer mechanisms and less duplicated state. A necessary repair may add focused code and tests; a new mechanism must justify its maintenance cost against an in-scope failure.

Fixes go into the reviewed project with a test; protocol lessons go into this note as rules, not stories.

## Repository

`uv run --python '>=3.12' --with-requirements requirements-test.txt pytest` (about 25 s on all cores; `pytest.ini` sets `-n auto`) and `git diff --check`. Runtime is Python 3.12+ stdlib plus the harness CLIs; there is no venv or lockfile — the runner command supplies the test dependencies in `requirements-test.txt` (Hypothesis, pytest, pytest-xdist). The suite is unittest classes; each test owns its `XCHECK_ROOT`, pools and fakes, so they run in parallel safely. Optional long acceptance: `uv run --python '>=3.12' --with-requirements requirements-test.txt pytest tests/acceptance_runtime.py` runs one isolated installed fake turn silent for 185 s and checks valid publication and pool release.

`tests/fake/harness` fakes `codex exec` and `claude -p` (`native_turn`), acpx and every ACP lane's server (`review_turn`), the capacity meters and the Keychain lookup; one set of modes drives both turn functions. `tests/test_xcheck.py` holds ACP correlation (`AcpCorrelation`), the Claude per-call audit and MCP boundaries, end-to-end runs, pools, Herdr ownership, capacity and validation; `tests/test_runtime_e2e.py` drives an isolated installed runtime through silent work, drafts before completion, explicit limits, cancellation, detachment and reattachment; `tests/test_final_repairs.py` guards terminal-answer precedence, spawn/setup cleanup, orphan identity and recovery, immutable queued inputs and compact activity; `tests/test_codex.py`, `tests/test_claude.py` and `tests/test_*_acp.py` cover each lane's chain, custody, controls and admission; `tests/test_view.py` checks the pane transcript against captured streams; `tests/test_laws.py` holds property laws for the answer grammar. `tests/conftest.py` gives every test session a disposable `HOME` (with only a Grok login stub and the fake Agy server) before `xcheck` is imported, so no test reads or copies the operator's configs, and refuses Python older than 3.12; tests also set `XCHECK_ROOT` to a disposable root. Never point a test at the real `/tmp/agent-offload`: it would queue behind live runs. Dropbox resets new files to mode 600; restore `755` on `bin/xcheck` and `tests/fake/harness`.

After changing `bin/` or `xcheck/`, run `bin/xcheck install`, then `xcheck doctor`. History is `git log`; durable requirements, invariants and limits live here, not in TODO or ledger files.

Native progress is diagnostic, never a termination or time-extension predicate. `activity` records event types and completed-tool counts without arguments, results or answer text. OpenCode additionally reads its local native store only after checking the exact session belongs to this lane workspace and was created for this run; it reports tool state and reasoning length/timestamps. An open tool can buffer output, and reasoning can advance without a completed stream part. Compare metadata to learn what changed; an unchanged snapshot is unknown. A corrupt message or part is skipped without discarding verified metadata from other rows; partial or unavailable native diagnostics are shown explicitly. Equal timestamp rows use sequence order. Native running metadata survives process death, so always pair it with current runner liveness. A blocked permission prompt remains pending until an explicit intervention; never resend the task or infer failure from CPU, spinner paint or missing heartbeats.
