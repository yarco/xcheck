# Multi-Agent Cross-Check Protocol

X-Check fans one immutable review packet out to **other** agent CLIs (Codex, Claude Code, Grok, Agy) as real processes, collects one answer file per lane, and leaves judgment to the orchestrating model. Codex and Claude run their own first-party headless streams and every other lane is an ACP session driven by acpx; one lane runner serves two placements: **headless** (child processes) and **Herdr** (one visible pane per lane, right of the orchestrator, showing that lane's ACP stream).

| Owner | Holds |
|---|---|
| This note | packet contract, invariants, harness facts and why they hold, limits, merge rules |
| `bin/xcheck` + `xcheck/` | everything with one mechanical right answer: exact argv, process groups, deadlines, capacity, locks, placement, stream parsing, validation, status |
| The orchestrator | judgment: roster, packet, diagnosing a failed lane and telling the operator, premise checks, adjudication, `CONSENSUS.md` |

The code never judges a finding and never retries; the model never improvises process control. Exact flags live only in `xcheck/adapters.py`; this note records why each non-obvious one is there.

Scope: one operator, one macOS machine, attended runs, possibly several orchestrator sessions running cross-checks at once. Reboot mid-run, adversarial peers, and unattended multi-hour recovery are outside the contract.

## Run it

```bash
xcheck doctor                                              # installed copy, flags, model pins
xcheck run --base /tmp/agent-offload/<slug> --orch claude  # default roster minus the orchestrator's harness
```

`xcheck` on PATH is `~/.local/bin/xcheck`, a read-only, content-addressed copy that `bin/xcheck install` publishes from this repo. `doctor` compares it with the source digest even when invoked through the copy. Reinstall after changing `bin/` or `xcheck/`.

1. **Stage** `BASE=/tmp/agent-offload/<slug>/` (Packet below). Stage and launch before loading unrelated material: every later return re-sends the whole context.
2. **Record** BASE, roster and the exact command in the existing task tracker or chat before spending. `run.json` persists the settings; write no separate handoff for a run.
3. **Announce**: `Fan-out: N peers → <lanes>. Not peers: <harness> (<why>)`.
4. **Run** without spending master-model turns: retain one blocking host operation or background job with a real completion callback. The local supervisor waits without inference. Do not schedule repeated short waits or model health prompts. Progress inspection may read only `xcheck activity` metadata; keep active findings, tool outputs and answer drafts unseen until settlement. Host notifications, repeated tool returns and large metadata outputs are not evidence of zero token use. A local wait invokes no model; subscription savings require a retained operation or verified completion callback without periodic model resumption.

   | Orchestrator | Form |
   |---|---|
   | Claude Code | `xcheck run …` as a background shell job; its completion notice is the one return |
   | Codex | absolute `~/.local/bin/xcheck run …` in a retained host shell operation, or `--detach` followed by one retained `xcheck wait --base B`. Keep shell polling inside the host tool, without returning to model sampling. The allow rule covers the installed absolute path followed by `run`, `wait`, `status`, `activity`, `cancel`, `doctor`, `capacity` or `models`; never point it at the vault source |
   | Grok | Herdr mode only. Background `xcheck run`, then retain its host completion operation; reaching a host wait cap detaches the waiter, never the reviewer |
   | opencode | `--detach` survives its shell call. Its shell tool has no background completion callback: disclose that integration gap and leave the durable BASE pending; do not repeatedly invoke the master to run short waits. Reattach on an explicit collection request or a verified host callback. `--orch opencode` drops opencode lanes |
   | pi | retain a host background completion job if available; otherwise detach and report BASE pending. Never pi's own delegate/subagent tools as peers |
   | Agy | retain a host completion job; `--orch agy` drops every Agy lane |
   | Devin | retain a host completion job; `--orch devin` drops Devin lanes |
   | anything else | `--orch other`; one retained wait/completion callback. Without that capability, detach and disclose pending collection. Never claim a different harness to bypass exclusion |

   `wait --timeout S` is for an explicit bounded status request. Exit 3 means still pending, and authorizes neither reviewer cancellation nor another scheduled master turn. `.done` is a durable completion record, not a host notification transport. Verify the host callback or retained-operation behavior; do not claim automatic resumption from a file write alone.

5. **Report** every non-`done` lane in the next chat message from `STATUS.json` (`reason`, `stderr_tail`): `<lane> <status> — <cause in plain words>. Fix: <remedy>. Continuing with <others>.` Also report MCP startup warnings and retrieval-policy diagnostics, including those on `done` lanes. Native completion and proof do not certify policy compliance; a successful unapproved call does not establish a charge.
6. **Merge** (below) into `BASE/CONSENSUS.md`.

`run` options: `--lanes kind:model[:effort],…` replaces the roster (Agy and Devin take no effort, OpenCode's is an optional ACP effort; every other kind needs one); `--add LANE` appends an opt-in lane to it. `--mode auto|headless|herdr` (auto = Herdr when available). `--web live` (default: peers may search and must cite what they relied on) or `packet` (built-in web tools off and peers told not to fetch; connected MCP tools remain, so this is not isolation). `--idle` and `--cap` are optional operator-requested cancellation limits; neither has a default. The caller must not invent a limit to guess how long a reviewer should take. Without a limit, a quiet lane and a queued lane remain pending until completion, an observed failure or explicit cancellation. A supplied `--cap` also bounds pool admission and arms the runner's watchdog; its expiry means policy stopped the work, never that the reviewer was idle. Silence cannot establish inactivity. `--force-lane NAME` launches a selected lane past a capacity refusal, only on the operator's say-so and announced in chat. `--skip-capacity` is for controlled smokes. `--detach` returns once launched.

Invalid options (a BASE that does not resolve under `/tmp/agent-offload`, no peers, non-positive budgets, a forced lane not in the roster, a same-kind peer) are refused before any pane, model or launch marker exists. Inside that root any slug works (spaces, quotes, non-ASCII, nesting, a relative path or a symlink that resolves there), and peers always run in the fixed `.lanes/<lane>` workspaces, so no BASE spelling reaches a trust or approval prompt. Other commands: `xcheck wait --base B [--timeout S]` (subscriber; reattaches without relaunch), `xcheck status --base B` (render from files), `xcheck activity --base B [--lane NAME] [--json]` (one compact line per lane; `--json` requests full metadata without peer findings), `xcheck cancel --base B [--lane NAME] --reason TEXT` (prevalidate all selected runner identities before signalling; preserve the operator’s reason in final status). Caller or supervisor interruption detaches; it never cancels peers.

Exit codes: 0 every lane settled (read the table); 2 refused before any spend; 3 `wait` timed out while lanes run; 130 supervisor interrupted.

Refresh pins deliberately after checking the installed CLIs: when the ACP server advertises a newer Flash or Pro, replace that one row. Claude pins use the versioned id (`claude-opus-5-5`, not `opus-5-5`); capacity maps it to the opus bucket. Effort tiers are per model: an older Grok given `xhigh` fails at launch rather than downgrading. An Agy selector carries its own effort (`gemini-3.8-flash-{low,medium,high}`); `xcheck doctor` lists what the ACP server advertises.

Opt-in only (`--add`; `adapters.OPT_IN`, pins checked by `doctor`): `devin:swe-2-max` (the operator's current Devin default), and the zero-price OpenCode pins `opencode:opencode/space-bunny-free`, `opencode:opencode/muse-spark-1.3-contributor-free` (a Contributor offer — it may log or train, so mind what its packet holds). The ACP server advertises only Gemini models, so third-party Agy selectors (Claude, GPT-OSS) are not available to lanes; xcheck refuses non-Gemini selectors before launch; acpx refuses an unadvertised Gemini `--model` before any turn. Other OpenCode extras are discovered dynamically with `xcheck models`, rather than maintained as model pins. Remove a vanished free pin instead of substituting its paid sibling; `openrouter/qwen/qwen3.8-27b:free` was absent from the client listing on 2026-10-06. Use `--add opencode:<provider>/<model>[:variant]`; an OpenRouter `:free` suffix is part of the model, with an optional variant after it. Slashes and colons become hyphens in lane names, and the exact model ID reaches OpenCode unchanged. Check the selected provider's data policy before sharing a packet; Contributor and some trial offers permit training or logging.

When the operator requests GLM 5.3 on the Z.ai coding-plan subscription, use `--add opencode:zai-coding-plan/glm-5.3:high` after checking `opencode models zai-coding-plan`. Keep the coding-plan provider and configured subscription credentials; never substitute a paid API provider. Claude remains a subscription lane in the default roster.

`xcheck models` reads provider-owned sources on every invocation. [OpenRouter's live model API](https://openrouter.ai/api/v1/models) reports prices, modalities and tool support. Zen's [live model list](https://opencode.ai/zen/v1/models) reports IDs only, so those IDs are joined to the endpoint and pricing tables on its [production documentation](https://opencode.ai/docs/zen/). A documented free model absent from the live list is omitted; System One decision models are excluded. Cerebras' [public pricing API](https://inference-docs.cerebras.ai/api-reference/models/public-models) is checked too; its current offers are paid and its expiring trial credits are not treated as free models. Every reported price component must be known and zero. A failed source omits that provider and reports the gap; there is no stale pricing fallback.

```bash
xcheck models                              # current provider-confirmed zero-price offers
xcheck models --provider openrouter --json # sources, exact selectors, client support and account variables
xcheck models --provider opencode          # Zen's live availability + current documented pricing
xcheck models --sources /path/sources.json # extend provider discovery without maintaining model IDs
```

`--provider` is repeatable and selects a discovery source; unknown sources are refused. `--limit` defaults to 20; undated offers appear first so newly published models are not hidden by lagging dates, then dated offers sort newest first. OpenCode's refreshed verbose listing supplies local client support and, for Zen, tool capabilities and advisory release dates. Its Models.dev prices and deprecation markers do not establish provider availability or price. New provider models missing from the client listing remain visible as `needs-client-setup`; only locally supported tool models get a printed `--add` selector. A locally deprecated model is also marked for client setup. OpenRouter creation dates come from its API; Zen's API generates a timestamp for every request, so those timestamps are never treated as model release dates. Sources and date provenance are included in JSON. Explicit `opencode/<model>` and unprefixed Zen lanes share one quota pool.

A sources file maps provider IDs to definitions and adds to or overrides the built-ins. Example: `{"vendor":{"format":"priced-json","models_url":"https://vendor.example/models","docs_url":"https://vendor.example/docs","auth_env":["VENDOR_API_KEY"]}}`. URLs must be public HTTPS without credentials; `auth_env` holds informational setup names only and does not change lane credentials; connect added providers through OpenCode’s stored auth or provider configuration. The lane environment retains only the existing explicitly permitted provider keys, not arbitrary keys declared by a discovery source. `priced-json` accepts a `data` array with `id`, `pricing.prompt/completion` and any other charges, text input/output modalities (under `architecture` or at top level), and `tools` under `supported_parameters` or `supported_features`. Optional `created` is an epoch release date, `expiration_date` an ISO date, and `deprecated`/router metadata exclude those models. The `zen` format uses the documented endpoint/pricing HTML tables. Other response formats need a focused adapter; unverified providers are never offered based on a third-party zero price.

Copy a ready `--add` selector into a new review run after connecting the provider and checking its account quota and data policy. Zero token prices do not establish account readiness or review reliability; some trial or Contributor offers permit logging or training. Discovery performs no inference, config edit, roster change, or automatic substitution. Sources checked 2026-10-01; no local model snapshot is stored deliberately, because the offers change.

Gemini Pro and Flash are different evidence: Flash is the ratifying lane (it tends to agree with the packet's claims, false ones included) and Pro is the one that disagrees, so keep Pro even when Flash also ends `done`. `done` certifies the output contract, not review quality. Same-family lanes (two lanes of one model family in a roster) are correlated. Returns diminish after about three strong, independent peers; add a lane for a distinct capability or failure hypothesis, not for volume. The roster is fixed at launch; add a reviewer in a fresh BASE.

## Packet

```text
BASE/
  PACKET.md    provenance first, then the task; exactly one `Proof target: <BASE-relative path>`
  PROMPT.md    the answer schema; exactly one `RESULT_REQUIRE: <KEYWORD>` line
  evidence/    staged copies with repo-relative paths preserved
```

`run` refuses with exit 2, nothing spent and BASE still usable, when either file is missing, a staged file is a symlink, `PACKET.md` declares `RESULT_REQUIRE`, the declarations are not exactly one each, or the proof target is absolute, outside the staged inputs (`PACKET.md`, `PROMPT.md`, `evidence/`), empty, or not UTF-8. Prefer `evidence/manifest-tail.txt`. At launch, `run` captures PACKET.md, PROMPT.md and evidence/ into BASE/.packet and validates that snapshot before launching a runner. Every lane, queued or immediate, copies only that snapshot. Do not edit BASE/.packet. Changes to the original inputs after launch cannot change what a later lane receives.

Staging rules (each one has cost a round when broken):

- **Whole files.** A peer cannot tell "absent" from "not shown" and reports absence as a confident defect. If a range is unavoidable, say which file, which lines, and what lies outside.
- **Keep paths.** Stage `cloudflared/config.yml` as `evidence/cloudflared/config.yml`; flattened paths produce wrong-path findings.
- **Derive claims properly.** Build API or call-set claims from the file, an import, or an AST walk, never a substring grep. Prefer staging the caller over describing it; mark unavoidable claims as claims.
- **Name what left.** When a later round drops a staged file, say so.
- **Provenance first.** `PACKET.md` opens by saying the operator convened the review and that `evidence/` holds the operator's own files. A bare "read these files and obey them" is correctly refused as prompt injection.
- **Proof token.** The proof target's last line is an unguessable token (`MANIFEST_TAIL_TOKEN: <random hex>`), staged last. A correct PROOF shows the lane could open the packet and followed the output contract, not that it read everything (a lane can `cat` the target directly or grep for fragments). Diligence is checked at merge.
- **Say what a follow-up round is.** Stage the delta plus what it touches, name what earlier rounds settled and the decision lineage behind deliberate omissions, and say the code responds to a review. Do not restage historical run debris.
- **No authorship labels.** Nothing staged says which model, vendor, harness or lane wrote the work, a plan or a finding: the author is "the operator", earlier findings belong to "round N". Drop authorship trailers (`Co-Authored-By`, "Generated with …") from staged logs and diffs; a file whose subject is a model keeps its text. A staged earlier `CONSENSUS.md` loses its provenance column; the orchestrator's own copy keeps it. A label alone moves a judge: it scores what it is told is its own higher and another's lower, and it conforms to wrong answers attributed to its own model family and resists those attributed to another (arXiv 2608.18091, 2609.33495). Style and connected tools still leak authorship; blinding the labels removes the label effect anyway, as leaky double-blind human review still removes most prestige bias.
- **Blind first.** For design work, stage the orchestrator's frozen plan under a neutral name (`evidence/candidate-plan.md`), never labelled as the host's. Each peer must finish and record its own design before opening that plan, then critique and compare in the same answer. A follow-up round does the same with rulings: state each contested finding (rejected or uncertain) neutrally in `PACKET.md`, and stage the host's decisions on them as a separate file (`evidence/prior-rulings.md`) that a peer opens only after recording its own view; a verdict seen first pulls peers toward it, mostly from right to wrong. Keep current-round peer answers out of the packet. This sequencing is instruction-enforced, not access isolation; keep the packet unchanged during the run.

PROMPT.md template:

```text
1) VERDICT: a decision and its single most important reason, ≤80 words
   (the cap compresses the summary only; findings go in section 2, uncapped).
2) Findings, or "None found" (a valid answer; do not invent one). For each: severity; evidence (file, symbol, behaviour); root cause;
   the mechanism and premises the diagnosis rests on; how often the scenario
   occurs and what ignoring it costs; the smallest repair (code or pseudodiff
   when the evidence allows); what must stay true; a verification that fails
   while the defect is present; confidence and missing context.
3) What you would delete from the target, and why deleting it is safe.
4) Alternatives worth considering (if any).
5) One-line recommendation.
6) PROOF: <the last non-empty line of the proof target, copied exactly>

The next line is packet metadata; do not include it in your answer.
RESULT_REQUIRE: VERDICT
Final line, alone: RESULT_COMPLETE
If you cannot do the review, make the final line RESULT_INVALID instead.
```

The markers are literal lines: no period, code fence, quote or explanation after `RESULT_COMPLETE` / `RESULT_INVALID`. PROOF is `6) PROOF: <token>`, or a bare `6) PROOF` heading followed by the token alone or by a `PROOF: <token>` line (bold, bullets or backticks around either are fine); anything else after `PROOF:` is compared as the token and fails, and so does pasting the whole proof file. An answer also needs review text beyond the heading, PROOF and marker. `tests/test_laws.py` states the whole grammar as properties.

**What every lane is told** (`run.MESSAGE`): the owner convened the review; read `PACKET.md` then `PROMPT.md` (PROMPT decides format); work from the staged directory; connected MCP tools are available, external actions (sending messages, changing records) are not; nobody answers questions mid-review. Codex, Claude and Agy use tools that read (plus web in live mode); Grok, OpenCode and Devin may also run Bash and write disposable scratch inside their own workspace, never the staged files. Every lane prints the answer as its final message; only native turn completion publishes it, so a complete-looking draft is not a publication signal.

**What `run` adds to BASE**: `run.json` (roster, contract, settings, Herdr pane ids; written once), `lanes/<lane>/` (`message.txt`, `staged` stamp, `pids.json`, `exit.json`, `stream.jsonl` + `view.log`, `stderr.log`, `harness.log` where the CLI supports one), `RESULT-<lane>.md` (the captured answer), `STATUS.json` / `STATUS.md` (one row per selected lane, skipped ones included). Peers work in stable workspaces `/tmp/agent-offload/.lanes/<lane>/`, restaged only after pool admission and reused by the next run of that lane; inspect a run's evidence in its BASE, not in a later run's workspace. Artifacts stay in `/tmp`; never copy run directories into the vault.

## Lane statuses

| Status | Meaning | Orchestrator action |
|---|---|---|
| `done` | answer ends `RESULT_COMPLETE`, has the required heading and review text, PROOF matches; policy diagnostics are separate | read, report diagnostics and adjudicate |
| `invalid` | an answer exists but breaks the contract (reason names how), or the peer declared `RESULT_INVALID` | read it anyway; its findings are leads; tell the operator |
| `failed` | no answer; reason is the harness's structured error, else its first stderr line | read `reason` + `stderr_tail`; tell the operator cause and remedy |
| `timeout` | idle limit, `--cap`, or the runner's own bound ended it | tell the operator; partial output is in `stream.jsonl` and any draft in `RESULT-<lane>.md` |
| `skipped` | never spent: capacity reserve, auth, unknown capacity, or pool busy past `--cap` | tell the operator; `--force-lane` only on their say-so |
| `interrupted` | a lane runner was signalled or explicitly cancelled | the final reason preserves an explicit cancellation reason; a signalled subscriber/supervisor only detaches |

Never relaunch a lane that died of quota or auth in the same run. A lane lost to a bad packet or prompt is rerun in a fresh BASE after fixing the packet, and the operator is told. A lane that dies within seconds with a usage message usually means a flag drifted: read the first stderr line, run `xcheck doctor`, and compare the installed CLI's `--help` before blaming quota or the model. The only answer channel is the lane's final message; a review written to a file instead ends `failed` and is not scouted. Read its saved stream, and the file in `/tmp/agent-offload/.lanes/<lane>/`, before the next run of that lane restages it.

## Placement and views

**Headless**: `run` starts a detached supervisor; the caller is a subscriber. Each lane runner owns its own process session. Losing or interrupting the subscriber/supervisor leaves lanes intact. Reattach with `wait`; only `cancel` intentionally stops a live lane.

**Herdr**: chosen only when the operator's `~/.agents/bin/herdr-caller-context` returns exit 0 with a `verified` binding (pane, session, socket and live terminal identity) and that pane's readable layout is at least 176×14. Title fragments, focused panes and inherited `HERDR_ENV=1` never establish caller identity. All placement operations target the verifier's exact socket and session, even if inherited context disagrees. A missing helper, unconfirmed/ambiguous context, incomplete binding or unreadable layout gives headless in auto mode; explicit Herdr mode refuses unavailable placement. Re-verify with `python3 -c 'from xcheck import herdr; print(herdr.caller())'` in a real caller and the ownership tests. The first lane splits right of the orchestrator (`--ratio 0.62`: the orchestrator keeps 62%); the rest split that column into equal rows in roster order, titled `xcheck:<lane>`. Lane panes are addressed only by the ids their split returned, never by title or focus, and never by `--current`. Each pane runs `exec <lane runner>`, so the pane is the runner: Herdr closes it when the runner exits, three seconds after its final line. Nothing closes panes by id. If the supervisor dies, panes finish on their own and `wait` reattaches.

**The stream**: every lane runs acpx `--format json exec`, and the runner reads the ACP JSON-RPC stream; the answer is the agent text after the last tool call. Native turn completion ends the review: the response to acpx's `session/prompt` with `stopReason=end_turn`. Any other stop reason (`cancelled`, `max_tokens`, `max_turn_requests`, `refusal`, unknown) fails. A process exit without completion fails and retains any text as a diagnostic draft; intermediate messages and completed tools never settle a lane. Validate the captured final answer before calling it usable. Stdout resets an explicitly requested idle clock; stderr does not.

acpx prints both directions without saying which, and JSON-RPC ids belong to the side that sent the request, so an agent request can reuse acpx's own ids (Agy's `session/request_permission` took id 0, acpx's `initialize` id). The reader therefore never assumes one id space. Only a `session/prompt` response carries `stopReason` (ACP schema), so that shape settles the turn whatever id it reuses. Every other request id, from either side, is counted until answered. An error carrying the prompt's id while another request with that id is open is held: the other response at that id says which side sent it, and if acpx exits first (acpx, the client, does know the direction, and exits non-zero after a failed prompt) the held error is the failure. Errors answering other requests, and acpx's own id-null errors (agent disconnected, `--model` refused), are kept as the reason only if the turn never completes. `tests/test_xcheck.py` `AcpCorrelation` holds both collision orders.

A native prompt error ends a lane as `failed`, even if its process keeps emitting retry events. A Codex `error` event (a reconnect notice) can recover, while `turn.failed` is terminal. OpenCode native upstream rate limits are excluded under the operator’s stated policy even if retrying. Quoted error text in a review is not a native error. Report the cause and exclude that lane from usable review coverage.

A timed-out, interrupted or failed lane retains that status even if it printed a complete-looking draft; an explicitly requested cap is checked before completion, and a partial answer never overrides the termination reason.

Completion is always the lane's `exit.json`, never pane text.

## Capacity

Each pool has one free meter that runs no inference, read by `xcheck/capacity.py`: Codex `app-server` `account/rateLimits/read` (5 h and weekly windows), Claude's OAuth usage endpoint with the keychain token (its `limits[]` list: session, weekly, and a weekly cap scoped to the lane's model family, where a scoped cap it cannot attribute counts; the flat `five_hour`/`seven_day` keys only when `limits[]` is absent), Grok's credits meter (the worse of the account and Grok Build usage percents on the CLI credits view; when that view has no percent, the same token's `GetGrokCreditsConfig` used-percent), and Agy's `agy -p /usage` (zero turns; the lane family's 5 h and weekly buckets). `xcheck capacity [--lanes …]` prints the readings with the same reserves `run` would apply. Each lane reads its own pool after admission and immediately before spending, so the reading is not stale and, in Herdr, runs outside any orchestrator sandbox. A lane spends only on `eligible`: the tightest window must have more than the reserve left, 10%, or `5 + 5n`% for the run's `n` lanes in one Agy family (capped at 90). The reserve protects the operator's interactive quota, which a runtime quota error arrives too late to protect. A meter that cannot be read is `capacity-unknown` and a rejected login is `auth-required`; with `reserve-low` they end the lane `skipped`. There is no fallback meter.

- Agy's `/usage` is served by its persistent headless `language_server`; a launchd agent keeps one running. Agy lanes spend through Antigravity's ACP server, which signs in with the same OAuth client as `agy` (`1071006060591`, found in its sign-in URL); the Gemini meter moved during an ACP review turn, so the meter and the lane share the pool.
- Claude `security` exit 36 is a locked login keychain (for example, from a remote session): run `keychain-unlock-gui` with the operator at the screen. Never `security unlock-keychain` from an agent shell: control returns before a password can be typed. `security show-keychain-info ~/Library/Keychains/login.keychain-db` checks the state without prompting. Otherwise pass a fresh reading from Claude Code's `/usage`, the lowest window shown, as `XCHECK_CLAUDE_REMAINING=<percent left>` and `XCHECK_CLAUDE_REMAINING_AT=<ISO time>` (at most 5 min old) in the environment the runner inherits, i.e. headless placement; it overrides the keychain, so unset both right after that one launch. Exit 44 means no login.
- The Claude meter checks the keychain token's millisecond `expiresAt` before HTTP, including a 60 s margin for the probe and clock skew. An expired or near-expiry token returns `auth-required`. The caller should make one supported non-inference refresh attempt: `env -u ANTHROPIC_API_KEY claude --safe-mode --no-session-persistence --tools "" --permission-prompts none -p /status`, then recheck `xcheck capacity --lanes claude:claude-opus-5-5:high`. Bound this startup probe to 55 s, remove any inherited nested-Claude identity variables, and verify the CLI still handles the recognized `/status` locally after upgrades. In Claude 2.1.287 print mode the command returns a local unavailable-headless message with no model query; startup still attempts native refresh. Exit 0 alone is not recovery: the capacity recheck decides. This uses native subscription auth with customizations disabled; it is not a review or a lane retry. If eligible, include Claude in a fresh BASE. If native refresh still fails or requires browser login/keychain unlock, report the specific blocker and ask the operator; use `env -u ANTHROPIC_API_KEY claude auth login --claudeai` only for that requested interactive sign-in. Never force an auth refusal, log out a working session, hand-roll refresh, or switch to API billing. `claude auth status` can still say logged in while the token is expired, and Anthropic can return 429 for that expired token. Malformed present expiry fails closed; missing expiry preserves the existing read path. No custom token refresh or fallback meter is used.
- The Claude usage endpoint also returns HTTP 429 when polled too often (CodexBar reads it too). The meter accepts positive finite `Retry-After` seconds or an HTTP date, otherwise 2, 4, 8, 16 s; zero/negative/nonfinite delays cannot spin. Requests and sleeps share a 30 s probe budget, with at most five requests, and then fail closed as `capacity-unknown`. A long throttle reports its delay and recheck remedy. Recheck with `xcheck capacity --lanes claude:claude-opus-5-5:high`; once it reads `eligible`, add the lane in a fresh BASE. `--force-lane` does not apply here: a launched BASE refuses a second `run`.
- A rejected Grok token may only be stale: running `grok` once refreshes it. The CLI credits view (`/v1/billing?format=credits`) can return the weekly period and balance fields without `creditUsagePercent` or a GrokBuild `usagePercent`. Balances, including zeros, are not a quota. When that view has no usage percent, the same token reads `GetGrokCreditsConfig` on `grok.com`, the credits config behind `/usage`. Each in-range field-1 fixed32 in a clean message is a used-percent, and the worse one binds (`left = 100 − used`). A frame that is not a clean protobuf message supplies no percent. If that percent is missing too, the meter stays `capacity-unknown`. Do not infer admission from balances.
- A reading is a snapshot. A healthy Agy family can still hit a per-model cap ("Individual quota reached"); that lane fails with the harness's own error and is not retried.

## Locking and liveness

A quota pool (codex, claude, grok, agy-gemini) is spent by one run at a time, for two reasons: a capacity reading means something only while no other run draws on that meter, and the stable workspace and immutable snapshot need one owner per lane name, which needs a single owner. Lanes of the same run share their pool; disjoint pools run in parallel. Under `/tmp/agent-offload/.pools/<pool>/`:

- `gate`: exclusive, held for an instant while one lane decides admission. `busy`: shared by the owning run's live lanes; only a gate holder takes it exclusively, and it converts to shared while still holding the gate. `owner`: the BASE that last took the pool; it says who may join an occupied pool and is not liveness evidence.
- A lane takes only its own pool, then reads capacity, stages its workspace and launches; it never waits for a second pool while holding one. Waiting for the gate and for `busy` share one deadline (`--cap`) and happen in the runner, without model calls.
- The harness inherits the `busy` descriptor, so a killed runner's orphan can spend only while the pool stays held, and the pool frees when the last holder exits. acpx gives the agent it starts only stdin, stdout and stderr, so an ACP lane's agent command starts with `xcheck hold`: under `gate` it joins only a pool that is still busy and owned by this BASE, exits 75 otherwise, and execs the server holding its own shared lock. The server then holds the pool exactly as a native harness does, even if acpx is killed alone. The runner covers spawn and setup with unconditional cleanup using the actual owned child, including a failed pids.json write. Cancellation signals are deferred while establishing ownership and settling the group; the child restores the inherited signal mask before exec. The whole group is settled before admission is released.
- Never delete or replace a lock file: a new pathname is a different lock. All runs share the host-local root; `XCHECK_ROOT` exists for test isolation, not to bypass contention. The locks coordinate cooperating runs; they are not a security boundary.
- A descendant that leaves the process group and outlives both runner and harness is out of scope: nothing in scope spends quota that way. If it kept the inherited descriptor, later runs on that pool remain queued (or end `skipped` under an explicit cap); find the holder with `lsof +D /tmp/agent-offload/.pools`.

Runner and supervisor liveness is an exclusive lock on their own `alive` file, released by the kernel on crash: no PIDs, no process table (a sandboxed Codex orchestrator may be denied `ps`). `pids.json` and `supervisor.pid` exist for diagnosis. `BASE/.launched` (atomic mkdir, created after every refusal check) makes a BASE launch once; `wait` reattaches and never relaunches. Every settled runner writes `exit.json` exactly once. A requested cap arms a kernel alarm at `2·cap + 300` s; the default has no elapsed-time alarm. Unknown startup remains pending rather than becoming a guessed failure after 90 s. A runner that dies without `exit.json` is settled by `wait`: it stops the orphaned harness only after `ps` confirms the command line names that lane's directory or workspace, never on a PID alone, and keeps existing output for diagnosis. Recovery (`wait` after a runner died, or a runner's own exception handler) replays the saved `stream.jsonl` through the same reader: an answer is usable only if that stream holds native completion without a native error; a complete-looking RESULT file alone cannot promote a draft. It rechecks exit.json after a liveness probe so an authoritative record published during the probe is preserved. OpenCode’s acpx argv names its workspace with `--cwd <work>`.

## Current limits

- Distinct model IDs can produce the same sanitised lane name; a roster with duplicate names is refused before launch. The exact ID remains in run metadata and argv.
- Claude registers only approved local/keyless MCP servers and blocks account connectors; packet mode omits its remote MCP retrieval servers. Other harnesses retain instruction-only MCP/web restrictions. Shells, connected local tools and native web tools prevent a general free-only network guarantee. `--web packet` is not a security boundary for untrusted material.
- Grok, OpenCode and Devin’s shell can write anywhere the operator can (Grok’s unrestricted profile is explicitly authorized; OpenCode’s attempted sandbox was dropped, and Devin’s sandbox hides the login), including another lane's scratch; their own-workspace limit is an instruction. Codex (read-only sandbox), Claude (no shell) and Agy (Seatbelt: workspace, lane home, Agy uv cache, Keychain) cannot.
- Agy lanes share `ROOT/.cache/agy-uv`, which every Agy lane may write, so one Agy lane could alter the uvx MCP packages another Agy lane runs. It never reaches the operator's uv cache.
- No Agy lane gets `fff` or `qmd`: the ACP server cannot start them (see Harness facts). Re-test after either server or the ACP server updates.
- Grok 1.0.46 and 1.0.49 refuse `read-only` startup on symlinked container-runtime endpoints such as OrbStack's `/var/run/docker.sock`. The operator chose unrestricted reviewer lanes so the running Docker integration stays intact. Do not remove the Docker alias or reintroduce that failing profile automatically.
- A turn that blocks silently (a native tool buffering output, a stuck login) remains pending unless the operator supplies `--cap`/`--idle` or cancels; silence is not evidence of inactivity.
- A Herdr failure after a split but before `pane run` leaves a pane with an idle shell; close it by hand. (A failed `exec` makes zsh exit, so that pane closes itself.) A placement failure known to the supervisor is settled explicitly. An unobserved runner startup remains pending; elapsed time does not prove it failed.
- Only an explicitly supplied `--cap` ends a lane on elapsed spend. It is a cancellation policy; rerun in a fresh BASE after recording lost work. Native session continuation cannot restore killed OS processes or deleted scratch.
- Blinding covers labels only. Style, the reasoning itself, and connected tools (pond session history, qmd over this vault) can still tell a peer who wrote something or how the host ruled.
- If a runner died and `ps` is unavailable, `wait` cannot confirm the orphan's identity and leaves it alone, noting that in the reason; its pool stays held until the orphan exits. Never kill a recorded PID on a guess.
- A full roster starts many MCP servers in the same second, which can exceed Keenable's 10 requests/s limit (HTTP 429); the lane that loses the race lacks that server for its session and keeps its built-in web tools.
- Claude lanes still read managed policy and `~/.claude.json` state. Grok lanes make one initial title-sampling call per session that no supported switch disables.
- `main` carries no locally patched dependency. The ACP forms of the Codex and Claude lanes, each with its local patch, are on the `acp/codex` and `acp/claude` branches; re-check their upstream trackers (Harness facts) at each upgrade.
- Captured fixtures cover live Codex exec answers, an unsupported-model failure and an exhausted 5 h window, an Agy ACP turn with the server's reused request id, a Devin ACP shell/read turn, an OpenCode ACP shell/fetch/MCP/read turn, Grok missing quota percentages, live Claude stream-json answers and a model failure, and a real successful disallowed Claude Cloudflare call. Fixtures omit credentials, response headers and account identifiers. Other native account quota/auth failures still need captured fixtures; invalid-model fixtures prove parser shape only.

## ACPX boundary

acpx (OpenClaw's ACP client, npm, on the official ACP SDK) transports the Grok, Agy, Devin and OpenCode lanes, unpatched. Its exec path passes its environment through, keeps the agent in its process group, kills the agent's tree on SIGTERM/SIGINT/SIGHUP, and holds an inherited descriptor itself but gives the agent only stdio. `xcheck hold` restores the server's pool custody.

What stays in xcheck for every lane: quota admission and pool locks, immutable packet snapshots, launch-once, the proof contract, environment scrub, answer selection and validation. An ACP `end_turn` is not a review: the reader selects the final message and `validate.check` decides. All ACP lanes refuse lane-changing acpx config keys before admission and disable acpx's filesystem/terminal tools (client capabilities only; each agent's own tools follow its native policy).

ACP standardizes transport and completion: initialization, sessions, prompt updates, tool/permission requests and the prompt response. It does not standardize OS sandboxes, credentials or proprietary configuration, so vendor policy stays explicit per lane: Grok profile + version admission, Agy Seatbelt, Devin overlay + accept-edits, OpenCode stock build mode. Optional features are negotiated. See [ACP overview](https://agentclientprotocol.com/protocol/v1/overview). Codex and Claude read their first-party streams instead: their ACP forms need third-party adapters, and those adapters needed local patches (see their branches under Harness facts). Never use acpx's built-in Codex/Claude names: they resolve npm caret ranges at launch.

## Deliberately absent

Legacy (archived in the private repo `yarco/multi-agent-cross-check-protocol`, never a launcher) solved problems this design does not have. Do not re-add these without a failure that happened within scope:

| Legacy mechanism | Why it is not needed |
|---|---|
| Credit/auth log-regex classifiers over whole logs | their only consumer was the retry decision, and prose that quoted a token killed healthy peers; structured errors name the cause and nothing retries |
| Late harvest, file scouting, provisional labels, detached cleanup worker, notices file | lanes are owned processes that end with `exit.json`; one declared answer channel; the orchestrator reports from `STATUS.json` |
| Spender claims, PGID fallback, boot identity, daemon reaper, global lock with live-lane scans | every spender is our runner or its child; kernel lock lifetime equals spender lifetime; per-pool admission keeps disjoint pools parallel |
| Supervisor watchdog, pane-close and pane-ownership bookkeeping | the runner's alarm bounds it; `exec` makes each pane close with its runner |
| Herdr `agent start` readiness, splash classifiers, prompt resend | the prompt is a file acpx sends as `session/prompt`; a quiet turn remains pending unless a native failure or explicit cancellation is observed |
| Agy stdin bundle, 192 KB cap, read-depth probe | file tools reach large packets; the probe was gameable by grep |
| Agy app view, its trust entry, `ANSWER.ready` for Agy, its quota banner | Agy runs through its ACP server; the stream carries the answer and native completion |
| Host router with note read-map, wait metrics, `LIVE_CHECK_CAP` gate | `--mode auto` places; the note fits one read; token discipline is structural; the cap was a prompt contract, not enforcement |
| Perplexity lane | not a default peer; its failure shapes stay documented in Legacy |
| An opencode reviewer agent or permission rules | the free tier refuses custom permission/tool sets; its workspace and retrieval restrictions remain instructions, and the dropped Seatbelt profile is not a boundary |
| Codex app view, `-o` fallback and trust editor | the exec stream's last `agent_message` is the answer (real captures always carry it), and exec needs no trust dialog or operator config write |
| Claude/Grok app views, `--view`, `ANSWER.md`/`ANSWER.ready` commitment, screen logs and limit-banner handling | every lane streams structured events in both placements; native completion is the only publication signal |
| Devin/OpenCode app views, `ANSWER.ready` for these lanes | Native ACP completion supplies the final answer in both placements |
| Runtime under `~/.agents` with per-start hash verification | `~/.local` is outside Codex's writable roots, so the read-only snapshot needs no re-verification |
| Snapshot pruning | a queued runner may still exec an older snapshot |
| Fallback quota meters (Agy language-server port scan, CSRF probing, desktop-token scraping; Grok monthly view), an outer retry layer, secret redaction of notes | each pool's one meter works; an unreadable meter fails closed; notes never carry payloads or tokens |

Proposals already rejected, with the reason:

| Proposal | Why not |
|---|---|
| Isolated HOME for Codex or Grok | splits auth files (Agy's lane `GEMINI_HOME` does not: its login is in the Keychain) |
| Remove Claude `--allowedTools` | `--tools` only lists tools; `--allowedTools` is what pre-approves them |
| Kill an orphan when `ps` is denied | PID reuse can kill an unrelated process |
| Shell-readiness wait before `pane run` | typeahead is buffered; a miss surfaces as `failed` |
| Scrub loader variables (`DYLD_*`, `PYTHON*`) | the installed copy runs `python -I`, and the Codex rule matches only the exact command |
| A bare `xcheck` pattern in the Codex rule; allowing `lane`/`install` | PATH hijack; those are not orchestrator commands |
| Automatic retries | a quota/auth death repeats; a bad packet needs a fresh BASE |
| Check the served model against the lane pin | only Claude's stream names the model that answered; Codex and opencode streams and the apps do not. Every lane passes an explicit model and no fallback flag (Claude's `--fallback-model` is never passed) |
| Hide lane names from the orchestrator during the merge | lane identity is evidence the merge uses (Flash ratifies, same-family lanes correlate), style names the lane anyway, and the orchestrator's bias runs toward its own work, which no label hides |
| Paraphrase or style-normalise answers to hide authorship | light perturbation helps, but full normalisation lets agreement with the judge's own views take over as the preference (arXiv 2512.05379), and a paraphrase can change what a finding claims |
| A self-preference warning in `PROMPT.md` or the merge | a one-line bias warning did not move self- or perceived-authorship effects when measured |
| Replace acpx with an in-house ACP client | it would delete `xcheck hold` and the acpx config guard, but xcheck would then own handshake, model and config-option selection across ACP revisions, and permission answers: the protocol layer acpx (on the official ACP SDK) maintains |
| Return Agy, Devin or OpenCode to their native CLIs or apps | `agy -p` ends the turn on any soft-denied tool, the apps need `ANSWER.md` commitment and can block on dialogs, OpenCode's app took no effort; ACP gives each a structured stream with native completion in both placements |
| Run Codex through codex-acp on `main` | the stock adapter reports failed turns as `end_turn`, persists sessions and spends a title turn; `codex exec` has none of these, so the ACP form waits on the `acp/codex` branch for upstream fixes |
| A direction-tagging acpx patch, or one patched client for every lane | the ACP shape already identifies prompt completion, and an id collision is resolved by the other response or by acpx's own exit; a second patch would add maintenance for no in-scope failure |
| A pre-prompt Grok `_x.ai/session/rename` to skip title sampling | verified on 1.0.50: the initial title is still sampled and discarded |
| Let peers rank each other's answers (council stage 2) | a judge favours its own entry even when anonymised, and a ranking is a preference, not a falsifiable finding |

## Merge

1. Re-read `STATUS.json` and every `RESULT-*.md`, `invalid` ones included, right before merging. A truncated draft is a lead only; never manufacture a peer's final position from it.
2. Check each concrete claim's **premises** against the real tree before its reasoning. The ratifying lane fails at the premise: it can reject a correct fix because it misread code it was shown. Absence-of-code, wrong-path and packet-claim findings are packet suspects: open the real file first. A finding is rejected as wrong only on an observation that contradicts its premise or mechanism (a file and line, a run, a live read), never on argument; without one it is uncertain. The orchestrator usually wrote what is under review, so it is the one judge no label can blind, and it favours its own work most where it is unsure; this rule turns that unsureness into an uncertain row instead of a rejection. Out-of-scope findings follow the admission rule.
3. Never tally reviewers. Agreement counts only when premises were derived independently; same-family lanes are correlated. Volume is not quality, and a small delta is no reason to drop the expensive lane.
4. Judge each repair separately from its diagnosis: a correct diagnosis does not make its repair correct. The verification must be able to fail while the defect is present; two checks that read the same state are one signal. When no independent check exists, record the limitation or ask the operator to check; never claim completeness. For stored state, test that omission preserves the last value unless the contract explicitly calls for deletion. When comparing designs, a peer's preference for its own design is not evidence; take only the defects it names in the others. Compare on the requirements the frozen plan stated before launch, and apply a requirement learned from a peer to every design, the plan included.
5. Write `CONSENSUS.md`: one decision line; a confirmed / rejected / uncertain table with lane provenance; for each confirmed finding the selected repair, its verification, and why the host chose it when it differs from the peer's; lanes with no usable answer, never counted as disagreement. Uncertain is a finished ruling, not an undecided one: list every uncertain row for the operator in the next chat message. If no peer produced substantive evidence, say the review is unverified and why; relaunching an unchanged packet is not progress.
6. Verify every applied fix with a regression that fails on the defect. Use a fresh peer round only when an admitted finding or uncertain contract requires independent evidence that local checks cannot provide; scope it to the delta and the contracts it touches, with the decision lineage staged. Do not spend another subscription round merely to ratify completed deterministic repairs. Stop when no admitted finding remains.

**Admission rule.** A finding earns code only if its failure has happened or is likely within scope, and then it gets a tested repair. A real but out-of-scope finding earns one line in Current limits. Anything else is rejected in `CONSENSUS.md` with its reason. Ask reviewers what they would delete, not only whether something is correct. Never add prose to pre-empt a reviewer. Prefer fewer mechanisms and less duplicated state. A necessary repair may add focused code and tests; a new mechanism must justify its maintenance cost against an in-scope failure.

Fixes go into the reviewed project with a test; protocol lessons go into this note as rules, not stories.

## Repository

`uv run --with-requirements requirements-test.txt pytest` (about 25 s on all cores; `pytest.ini` sets `-n auto`) and `git diff --check`. Runtime is Python 3.12+ stdlib plus the harness CLIs; there is no venv or lockfile — the runner command supplies the test dependencies in `requirements-test.txt` (Hypothesis, pytest, pytest-xdist). The suite is unittest classes; each test owns its `XCHECK_ROOT`, pools and fakes, so they run in parallel safely. Optional long acceptance: `uv run --with-requirements requirements-test.txt pytest tests/acceptance_runtime.py` runs one isolated installed fake turn silent for 185 s and checks valid publication and pool release.

`tests/fake/harness` fakes `codex exec` and `claude -p` (`native_turn`), acpx and every ACP lane's server (`review_turn`), the capacity meters and the Keychain lookup; one set of modes drives both turn functions. `tests/test_xcheck.py` holds ACP correlation (`AcpCorrelation`), the Claude per-call audit and MCP boundaries, end-to-end runs, pools, Herdr ownership, capacity and validation; `tests/test_runtime_e2e.py` drives an isolated installed runtime through silent work, drafts before completion, explicit limits, cancellation, detachment and reattachment; `tests/test_final_repairs.py` guards terminal-answer precedence, spawn/setup cleanup, orphan identity and recovery, immutable queued inputs and compact activity; `tests/test_codex.py`, `tests/test_claude.py` and `tests/test_*_acp.py` cover each lane's chain, custody, controls and admission; `tests/test_laws.py` holds property laws for the answer grammar. Tests set `XCHECK_ROOT`, `CODEX_CONFIG` and `XCHECK_AGY_ACP_DIR` to disposable paths; never point them at the real `/tmp/agent-offload` (they would queue behind live runs) or the real configs. Dropbox resets new files to mode 600; restore `755` on `bin/xcheck` and `tests/fake/harness`.

After changing `bin/` or `xcheck/`, run `bin/xcheck install`, then `xcheck doctor`. History is `git log`; durable requirements, invariants and limits live here, not in TODO or ledger files.

Native progress is diagnostic, never a termination or time-extension predicate. `activity` records event types and completed-tool counts without arguments, results or answer text. OpenCode additionally reads its local native store only after checking the exact session belongs to this lane workspace and was created for this run; it reports tool state and reasoning length/timestamps. An open tool can buffer output, and reasoning can advance without a completed stream part. Compare metadata to learn what changed; an unchanged snapshot is unknown. Native running metadata survives process death, so always pair it with current runner liveness. A blocked permission prompt remains pending until an explicit intervention; never resend the task or infer failure from CPU, spinner paint or missing heartbeats.
