`xcheck models` reads provider-owned sources on every invocation. OpenCode’s advisory client metadata comes from the V2 native catalog, which uses its bundled/cache snapshot and performs TTL-based background refresh; this call does not force a synchronous Models.dev refresh. Provider prices and served IDs are still fetched live, so stale advisory metadata can leave a new free offer needing client setup but cannot establish its price. [OpenRouter's live model API](https://openrouter.ai/api/v1/models) reports prices, modalities and tool support. Zen's [live model list](https://opencode.ai/inference/v1/models) reports IDs only, so those IDs are joined to the endpoint and pricing tables of its console docs. The [deployed docs page](https://opencode.ai/v2/docs/console/models/) serves HTML tables, read with the standard-library HTML parser. No source branch, markdown fallback, login, browser or inference is used by discovery. Tables with ambiguous headers, duplicate identities, merged cells, incomplete rows or missing charge columns fail closed. The live-list join omits documented models that are not served. A documented free model absent from the live list is omitted; System One decision models are excluded. Cerebras' [public pricing API](https://inference-docs.cerebras.ai/api-reference/models/public-models) is checked too; trial credits are not treated as standing free models, and only offers with all reported charges known and zero can qualify. Every reported price component must be known and zero. All discovery formats require tools, text among their input modalities and text-only output. Additional image, audio or video inputs do not disqualify a coding model; image/audio/video-only inputs and non-text outputs are excluded. Offers with an announced end date are also excluded as promotions rather than standing free tiers. A failed source omits that provider and reports the gap; there is no stale pricing fallback.

```bash
xcheck models                              # current provider-confirmed zero-price offers
xcheck models --provider openrouter --json # sources, exact selectors, client support and account variables
xcheck models --provider opencode          # Zen's live availability + current documented pricing
xcheck models --sources /path/sources.json # extend provider discovery without maintaining model IDs
```

`--provider` is repeatable and selects a discovery source; unknown sources are refused. `--limit` defaults to 20; undated offers appear first so newly published models are not hidden by lagging dates, then dated offers sort newest first. OpenCode's native `model.list` API supplies local client support and, for Zen, tool capabilities and advisory release dates. Its Models.dev prices and deprecation markers do not establish provider availability or price. New provider models missing from the client listing remain visible as `needs-client-setup`. A ready model prints `--add` when it is in neither `OPT_IN` nor `DEFERRED`, `pinned` or `deferred` when it is. Separately from those marks, each queried provider's read is `ok`, `failed`, or `empty` over its pre-filter rows — the documented exact served ids and their price state, before endpoint/client capability filters and `--limit`. Zen also reports `served_ids` from the raw live inventory, so an undocumented live id is distinguishable from a vanished one. A pin's verdict reads only its own provider's read: `free` while the exact id is served at zero price (client `tools: false`, missing metadata, or `needs-client-setup` never change that), `gone` only when the read is `ok` and the exact id is absent from the live inventory or parsed at a price above zero, and `unknown` when the read failed, joined to no rows, was never queried, or served the id with a price that did not parse. `missing` prints only for a `gone` pin; an `unknown` provider prints none. Marks and verdicts are computed on the full result, before `--limit`. A locally deprecated model is also marked for client setup. OpenRouter creation dates come from its API; Zen's API generates a timestamp for every request, so those timestamps are never treated as model release dates. Sources, per-provider reads, per-pin verdicts and date provenance are included in JSON. Explicit `opencode/<model>` and unprefixed Zen lanes of one model share one pool.

A sources file maps provider IDs to definitions and adds to or overrides the built-ins. Example: `{"vendor":{"format":"priced-json","models_url":"https://vendor.example/models","docs_url":"https://vendor.example/docs","auth_env":["VENDOR_API_KEY"]}}`. URLs must be public HTTPS without credentials; `auth_env` holds informational setup names only and does not change lane credentials; connect added providers through OpenCode’s stored auth or provider configuration. The lane environment retains only the existing explicitly permitted provider keys, not arbitrary keys declared by a discovery source. `priced-json` accepts a `data` array with `id`, `pricing.prompt/completion` and any other charges, text input/output modalities (under `architecture` or at top level), and `tools` under `supported_parameters` or `supported_features`. Optional `created` is an epoch release date, `expiration_date` an ISO date, and `deprecated`/router metadata exclude those models. The `zen` format reads deployed HTML endpoint/pricing tables. Other response formats need a focused adapter; unverified providers are never offered based on a third-party zero price.

### Cline free models

`xcheck models --provider cline` reads Cline's live [recommended-model feed](https://api.cline.bot/api/v1/ai/cline/recommended-models). Only exact IDs in its `free` array with a dedicated `cline-free/` prefix or `-free`/`:free` suffix qualify; ordinary paid IDs temporarily featured as free are omitted. ClinePass and Cloud offers do not qualify. The installed SDK's live catalog supplies advisory capabilities, including defaults for newly listed models; native file-read/completion/proof qualification establishes actual usability. A missing CLI/login is a client gap, and a failed feed never deletes last-good membership. Free access is checked again under admission. No paid or alternate model fallback is enabled.

Select `--add cline:<exact-id>[:thinking]`; Cline remains opt-in. Its account shares one pool. A per-model free-quota refusal preserves that route during maintenance and leaves other models eligible. There is no non-inference quota meter or promised allowance. [Cline's terms](https://docs.cline.bot/getting-started/free-models) describe rotating limited promotions and possible model-improvement use of free data.

Verified with Cline 3.0.74 (2026-10-27): its ACP inventory omits dedicated promotion IDs and can select a paid default for an unknown ID, so this lane uses the native headless `--json --provider cline --model <exact-id>` path. Only `run_result` with `finishReason=completed`, provider `cline` and the exact requested model ID publishes an answer. Draft events, errors, aborts and a plain process exit cannot complete it. JSON stderr carries startup/provider errors and is included in recovery. The minimum native mistake limit is 1; HTTP/internal retries remain native behavior. The direct platform executable retains the runner's pool descriptor; npm's JavaScript wrapper drops inherited descriptors and is not used.

Lane config/session/MCP data are isolated beside its logs, while `CLINE_PROVIDER_SETTINGS_PATH` keeps native OAuth refresh in the canonical login store. Inherited `CLINE_*` overrides and API keys are scrubbed. Shell, workspace limits, external-action restrictions and packet-mode network limits remain instructions; this is no OS sandbox. After upgrades, recheck native flags, exact model identity, file/shell tools and completion in both placements. Captured `cline-native-ok.jsonl` is regression evidence, not a current inventory.

### Additional free providers through OpenCode

Kilo uses the same native OpenCode ACP lane, output contract and pool custody as Zen. No dsh, relay, provider CLI or patched dependency is required. Discover them with `xcheck models --provider kilo`; add an exact qualified selector with `--add opencode:<provider>/<model>`. These are opt-in offers, never additional default reviewers. The provider and exact wire ID remain distinct even when two offers name the same model.

- **Kilo:** [live catalog](https://api.kilo.ai/api/gateway/models); admission requires `isFree: true`, known zero input/output and every reported charge, tools and text output. Auto routers, expiring offers and unsuitable modalities are excluded. The [gateway documentation](https://kilo.ai/docs/gateway/models-and-providers) reports anonymous access limited to 200 requests/hour/IP as checked 2026-10-24. Free-model data terms may permit logging/training.

For these providers xcheck generates native V2 `providers` configuration from the same live listing used for discovery. Admission fetches it again immediately before launch and refuses a selected offer that is no longer eligible. Each lane has its own empty `OPENCODE_DB` under its run directory, so a paid provider login from the operator's store cannot be inherited. The title agent is pinned to the selected free model. `xcheck models` performs no inference, Keychain read or persistent client configuration edit; its JSON includes only public client configuration and credential variable names.

Kilo needs no credential. Its lanes use an empty isolated native database; no operator key is loaded. AnyRouter was removed on 2026-11-02: the exhausted five-request trial requires a Go subscription or donated provider key, outside the free-only policy. It is neither discovered nor admitted.

An optional roster producer should qualify each exact route independently: one provider's successful answer cannot certify another route to the same model. Record the qualification time, model/provider, native versions, completion and proof. Respect provider rate limits and data terms; unknown prices or access do not authorize inference. Distinguish an unprobed or deferred route from a failed probe. A failed provider read does not establish that a model disappeared. Equivalent offers remain correlated at review selection and merge.

**Optional external free-roster refresh.** The runner consumes a local JSON object with a `lanes` list; it installs no scheduler and never writes that file. If you supply a producer, give the roster one writer, validate the complete candidate update and replace it atomically. Preserve the last-good file on incomplete observations without treating it as fresh price or access evidence. Qualification on one machine does not prove that another machine has the required native runtime, login or model inventory; keep those observations separate. Scheduling, credentials, deployment topology and monitoring belong to the adopting operator, not this package. You can instead select verified offers explicitly with `--add`; see [local integration](local-integration.md).

Roster membership certifies access and a tool-using answer, not review quality. Select general or coding models for a plausible review role; prefer a qualified route with available capacity; equivalent offers provide alternate access, not independent reviewers. A model's opaque name, missing size or recent release is not evidence of unsuitability. Domain specialization, correlated family coverage and measured review quality inform task selection; they do not establish price or availability.

`adapters.DEFERRED` stays available for an operator decision to hold a passing offer out of routine use; it records an observed run outcome, never an inferred permanent defect. An endpoint error, silence, operator cancellation or malformed final answer alone does not establish model unsuitability; a later qualification may reassess it.

Zero token prices do not establish account readiness or review reliability; some trial or Contributor offers permit logging or training. `xcheck models` itself performs no inference, config edit or roster change; a separately configured producer, if any, owns roster updates, and nothing substitutes one model for another. Each discovery or lane-check result is an observation for that day, not a guarantee for a later run.

A reviewer may agree with a packet's claims without checking them. Assess findings against source evidence; `done` certifies the output contract, not review quality. Same-family lanes are correlated. Prefer a small set of strong, independent peers; add a lane for a distinct capability or failure hypothesis, not for volume. The roster is fixed at launch; add a reviewer in a fresh BASE.


## Placement and views

**Headless**: `run` starts a detached supervisor; the caller is a subscriber. Each lane runner owns its own process session. Losing or interrupting the subscriber/supervisor leaves lanes intact. Reattach with `wait`; only `cancel` intentionally stops a live lane. It also settles a lane whose runner already exited (as `wait` would) or never started, so one such lane does not block cancelling the rest.

**Herdr**: chosen only when the configured caller-context helper (see [adapter contract](local-integration.md#herdr-caller-context-adapter)) returns exit 0 with a `verified` binding (pane, session, socket and live terminal identity) and that pane's readable layout is at least 176×14. Title fragments, focused panes and inherited `HERDR_ENV=1` never establish caller identity. The caller-context adapter owns native-session identity verification, including detached or sandboxed callers; xcheck does not infer that identity from its own process ancestry. All placement operations target the verifier's exact socket and session, even if inherited context disagrees. A missing helper, unconfirmed/ambiguous context, incomplete binding or unreadable layout gives headless in auto mode; explicit Herdr mode refuses and names the observed blocker (the helper state, an incomplete binding, the measured layout area, or the layout call's error). Re-verify with `python3 -c 'from xcheck import herdr; print(herdr.caller())'` in a real caller and the ownership tests. The first lane splits right of the orchestrator (`--ratio 0.62`: the orchestrator keeps 62%); the rest split that column into equal rows in roster order, titled `xcheck:<lane>`. Lane panes are addressed only by the ids their split returned, never by title or focus, and never by `--current`. Each pane runs `exec <lane runner>`, so the pane is the runner: Herdr closes it when the runner exits, three seconds after its final line. Nothing closes panes by id. If the supervisor dies, panes finish on their own and `wait` reattaches.

**The pane**: a Herdr pane and headless `view.log` show the same display of stream events the runner has already parsed. The header names the lane, model, effort, pid and start time; the launch argv is not on that screen. Each tool is one line with its key argument (path, query, URL, command, or `server.tool`) and ✓ or ✗ when the stream reports the outcome. Thought and message text are wrapped paragraphs; long thought is trimmed, and file contents and search results are not printed. ANSI styling is used only when stdout is a terminal, so `view.log` stays plain. After the final status line the pane names `RESULT-<lane>.md`, and prints the answer's opening lines when that text was not already shown. The pane is not a completion signal.

**The stream**: one runner reads each lane's structured stream, and only that harness's native turn completion ends the review. Codex (`codex exec --json`): the answer is the last `agent_message` after the last tool item, `turn.completed` ends the turn and `turn.failed` fails it. Claude (`claude -p --output-format stream-json`): the `result` event ends the turn and carries the answer; `is_error: true` makes it a failure. Grok, Agy, Devin and OpenCode run acpx `--format json exec` and the runner reads the ACP JSON-RPC stream: the answer is the agent text after the last tool call, and the response to acpx's `session/prompt` with `stopReason=end_turn` ends the turn; any other stop reason (`cancelled`, `max_tokens`, `max_turn_requests`, `refusal`, unknown) fails. A process exit without completion fails and retains any captured text as a diagnostic draft (Claude's text arrives only with its result, so a Claude lane that exits early keeps none); intermediate messages and completed tools never settle a lane. Validate the captured final answer before calling it usable. Stdout resets an explicitly requested idle clock; stderr does not. Once the harness exits, the runner reads its stdout until 3 s of silence (`DRAIN`; completion is always written before exit) and then ends the group, so a descendant holding that stdout cannot keep the lane pending.

For the ACP lanes: acpx prints both directions without saying which, and JSON-RPC ids belong to the side that sent the request, so an agent request can reuse acpx's own ids (Agy's `session/request_permission` took id 0, acpx's `initialize` id). The reader therefore never assumes one id space. Only a `session/prompt` response carries `stopReason` (ACP schema), so that shape settles the turn whatever id it reuses. The first `session/prompt` request is acpx's (it sends one, `--prompt-retries 0`, and the method is client-to-agent); a later one is counted like any other request. Every other request id, from either side, is counted until answered; a sender reuses an id only after its earlier request at that id is answered. An error carrying the prompt's id while another request with that id is open is held: the other response at that id says which side sent it, and if acpx exits first (acpx, the client, does know the direction, and exits non-zero after a failed prompt) the held error is the failure; a new request at that id instead proves the held error answered the earlier request at it. Errors answering other requests, and acpx's own id-null errors (agent disconnected, `--model` refused), are kept as the reason only if the turn never completes. acpx's own errors carry `data.acpxCode` and often `detailCode` (`RUNTIME/AGENT_SPAWN_ENOENT`, `USAGE`, `TIMEOUT`); the reason leads with them, so it names the cause without parsing prose. `tests/test_xcheck.py` `AcpCorrelation` holds both collision orders.

A native prompt error ends a lane as `failed`, even if its process keeps emitting retry events. A Codex `error` event (a reconnect notice) can recover, while `turn.failed` is terminal. OpenCode native upstream rate limits are excluded under the current lane policy even if retrying. Quoted error text in a review is not a native error. Report the cause and exclude that lane from usable review coverage.

A timed-out, interrupted or failed lane retains that status even if it printed a complete-looking draft; an explicitly requested cap is checked before completion, and a partial answer never overrides the termination reason.

Completion is always the lane's `exit.json`, never pane text. The shared settlement policy handles normal execution, runner exceptions and dead-runner replay. A termination decision is written to `termination.json` before cleanup and outranks salvaged completion; it is recovery input, not another completion signal. Display failure disables the display and becomes a diagnostic while execution continues. Owned-process cleanup runs even if final display flushing fails.

## Capacity

Each pool has one free meter that runs no inference, read by `xcheck/capacity.py`: Codex `app-server` `account/rateLimits/read` (5 h and weekly windows), Claude's OAuth usage endpoint with the keychain token (its `limits[]` list: session, weekly, and a weekly cap scoped to the lane's model family, where a scoped cap it cannot attribute counts; the flat `five_hour`/`seven_day` keys only when `limits[]` is absent), Grok's credits meter (the worse of the account and Grok Build usage percents on the CLI credits view; when that view has no percent, the same token's `GetGrokCreditsConfig` used-percent), and Agy's `agy -p /usage` (zero turns; the lane family's 5 h and weekly buckets; Argon uses its own weekly-only `gemini-argon-wtu-weekly` group). `xcheck capacity [--lanes …]` prints the readings with the same reserves `run` would apply. Each lane reads its own pool after admission and immediately before spending, so the reading is not stale and, in Herdr, runs outside any orchestrator sandbox. A lane spends only on `eligible`: the tightest window must have more than the reserve left, 10%, or `5 + 5n`% for the run's `n` lanes in one Agy family (capped at 90). The reserve protects the operator's interactive quota, which a runtime quota error arrives too late to protect. A meter that cannot be read is `capacity-unknown` and a rejected login is `auth-required`; with `reserve-low` they end the lane `skipped`. There is no fallback meter.

- Agy's `/usage` is served by its headless `language_server`; provision and maintain that native service separately. Agy lanes spend through Antigravity's ACP server, which signs in with the same OAuth client as `agy` (`1071006060591`, found in its sign-in URL); the Gemini meter moved during an ACP review turn, so the meter and the lane share the pool. That holds only while the `agy` CLI login (whose language server answers `/usage`) and the ACP server's Keychain login name the same account. With the optional local `agy_rotate_command` ([local integration](local-integration.md)), a run that reads a selected Agy lane below its reserve asks that command once, before any lane is admitted, to switch the whole account to one covering every selected Agy lane's buckets. The result is recorded in `BASE/agy-rotation.json`, and the lanes are then admitted as usual. Report a rotation, or a failed one, with the lane rows. A lane already skipped `reserve-low` in an earlier run needs a fresh BASE.
- Claude `security` exit 36 is a locked login keychain (for example, from a remote session): unlock the login Keychain interactively with the operator at the screen. Never `security unlock-keychain` from an agent shell: control returns before a password can be typed. `security show-keychain-info ~/Library/Keychains/login.keychain-db` checks the state without prompting. Otherwise pass a fresh reading from Claude Code's `/usage`, the lowest window shown, as `XCHECK_CLAUDE_REMAINING=<percent left>` and `XCHECK_CLAUDE_REMAINING_AT=<ISO time>` (at most 5 min old) in the environment the runner inherits, i.e. headless placement; it overrides the keychain, so unset both right after that one launch. Exit 44 means no login.
- The Claude meter checks the keychain token's millisecond `expiresAt` before HTTP, including a 60 s margin for the probe and clock skew. An expired or near-expiry token returns `auth-required`. At ordinary lane admission, while holding the Claude pool, xcheck makes one supported non-inference native refresh: `claude --safe-mode --no-session-persistence --tools "" --permission-prompts none -p /status`, bounded to 55 s by an owned watchdog, in the scrubbed subscription environment. The watchdog holds the pool/authentication locks and settles the native process on runner EOF, including abrupt runner death; the refresh bound survives its caller. The meter is reread; exit 0 alone is never recovery. If authentication is still required and an executable `claude_login_command` is configured ([local integration](local-integration.md)), xcheck invokes it once and waits for attended native sign-in, then rereads capacity and verifies the first-party subscription source before continuing the **same pending lane**. Only an eligible reading admits inference. The phases are `refreshing_auth` and `waiting_for_login`. Same-run Claude lanes serialize recovery and reread after waiting; different runs remain excluded by the quota pool. A missing native login may enter recovery, but unknown startup, a different authentication source, missing native limit flags, a locked Keychain, reserve-low and unknown capacity never trigger login. Diagnostic `capacity`/`doctor`, forced lanes and `--skip-capacity` never recover. Without a helper, or after failed sign-in, the lane skips with its admission reason. With an explicit `--cap`, pool waiting and Claude capacity/authentication share one admission deadline, including blocking meter and native-source probes; the review retains its separate spend cap. Expiry during authentication is `timeout` with no review started. No attended-login timeout is invented otherwise. Cancellation stops the owned helper and native refresh without starting a review. OAuth URLs, codes and native output are suppressed from run artifacts; the optional helper keeps unavoidable sign-in/code interaction in its dedicated visible window. Never force an auth refusal, log out a working session, hand-roll OAuth/refresh, change model/account automatically, retry a review turn or switch to API billing. `claude auth status` may still say logged in while the token is expired, and Anthropic can return 429 for that token. Malformed present expiry fails closed; missing expiry preserves the existing read path. No custom token refresh or fallback meter is used. Requalify the recognized local `/status` command and browser dispatch after CLI upgrades: on 2026-10-24 Claude 2.1.310 still handles `/status` locally in print mode and its native browser dispatcher invokes `BROWSER` directly on macOS.
- The Claude usage endpoint also returns HTTP 429 when polled too often (CodexBar reads it too). The meter accepts positive finite `Retry-After` seconds or an HTTP date, otherwise 2, 4, 8, 16 s; zero/negative/nonfinite delays cannot spin. Requests and sleeps share a 30 s probe budget, with at most five requests, and then fail closed as `capacity-unknown`. A long throttle reports its delay and recheck remedy. Recheck with `xcheck capacity --lanes claude:claude-opus-5-5:high`; once it reads `eligible`, add the lane in a fresh BASE. `--force-lane` does not apply here: a launched BASE refuses a second `run`.
- A rejected Grok token may only be stale: running `grok` once refreshes it. The CLI credits view (`/v1/billing?format=credits`) can return the weekly period and balance fields without `creditUsagePercent` or a GrokBuild `usagePercent`. Balances, including zeros, are not a quota. That view omits the percent even while usage is above zero, so its silence is not a reading. When it has no usage percent, the same token reads `GetGrokCreditsConfig` on `grok.com`, the credits config behind `/usage`. The meter decodes that message the way grok.com's `/usage` code does: a unified-billing config (`isUnifiedBillingUser`, field 11, true) with no `creditUsagePercent` (field 1) has used 0%. Proto3 omits a zero float, and every observed percent is a whole number, so a week's usage below 1% arrives with no field. This can occur after a weekly reset; the missing float alone is not evidence of a broken meter. Otherwise used is the worse of field 1 and each product-usage percent (field 7), and `left = 100 − used`. A frame or nested message that is not clean protobuf, a missing or non-unified config, more than one data frame, or a percent outside 0..100 supplies nothing, and the meter stays `capacity-unknown`. Do not infer admission from balances. Re-read the web client's `/usage` decoding if the config's shape changes.
- A reading is a snapshot. A healthy Agy family can still hit a per-model cap ("Individual quota reached"); that lane fails with the harness's own error and is not retried.

## Locking and liveness

A quota pool (codex, claude, grok, agy-gemini; for OpenCode, which has no meter, one pool per Zen model and one per other provider) is spent by one run at a time, for two reasons: a capacity reading means something only while no other run draws on that meter, and the stable workspace and immutable snapshot need one owner per lane name, which needs a single owner. Lanes of the same run share their pool; disjoint pools run in parallel. Under `/tmp/agent-offload/.pools/<pool>/`:

- `gate`: exclusive, held for an instant while one lane decides admission. `busy`: shared by the owning run's live lanes; only a gate holder takes it exclusively, and it converts to shared while still holding the gate. `owner`: the BASE that last took the pool; it says who may join an occupied pool and is not liveness evidence.
- A lane takes only its own pool, then reads capacity, stages its workspace and launches; it never waits for a second pool while holding one. Waiting for the gate and for `busy` share one deadline (`--cap`) and happen in the runner, without model calls.
- The harness inherits the `busy` descriptor, so a killed runner's orphan can spend only while the pool stays held, and the pool frees when the last holder exits. acpx gives the agent it starts only stdin, stdout and stderr, so an ACP lane's agent command starts with `xcheck hold`: under `gate` it joins only a pool that is still busy and owned by this BASE, exits 75 otherwise, and execs the server holding its own shared lock. The server then holds the pool exactly as a native harness does, even if acpx is killed alone. The runner covers spawn and setup with unconditional cleanup using the actual owned child, including a failed pids.json write. Cancellation signals are deferred while establishing ownership and settling the group; the child restores the inherited signal mask before exec. The whole group is settled before admission is released.
- Never delete or replace a lock file: a new pathname is a different lock. All runs share the host-local root; `XCHECK_ROOT` exists for test isolation, not to bypass contention. The locks coordinate cooperating runs; they are not a security boundary.
- A descendant that leaves the process group and outlives both runner and harness is out of scope: nothing in scope spends quota that way. If it kept the inherited descriptor, later runs on that pool remain queued (or end `skipped` under an explicit cap); find the holder with `lsof +D /tmp/agent-offload/.pools`.

Runner and supervisor liveness is an exclusive lock on their own `alive` file, released by the kernel on crash: no PIDs, no process table (a sandboxed Codex orchestrator may be denied `ps`). `pids.json` and `supervisor.pid` exist for diagnosis. `BASE/.launched` (atomic mkdir, created after every refusal check) makes a BASE launch once; `wait` reattaches and never relaunches. Every settled runner writes `exit.json` exactly once. A requested cap arms a kernel alarm at `2·cap + 300` s; the default has no elapsed-time alarm. Unknown startup remains pending rather than becoming a guessed failure after 90 s. A runner that dies without `exit.json` is settled by `wait`: it stops the orphaned harness only after `ps` confirms the command line names that lane's directory or workspace, never on a PID alone, and keeps existing output for diagnosis. Recovery (`wait` after a runner died, or a runner's own exception handler) replays the saved `stream.jsonl` through the same reader: an answer is usable only if that stream holds native completion without a native error; a complete-looking RESULT file alone cannot promote a draft. It rechecks exit.json after a liveness probe so an authoritative record published during the probe is preserved. OpenCode’s acpx argv names its workspace with `--cwd <work>`.

## Harness facts

`xcheck doctor` checks that every flag the adapters use appears in the installed CLI's `--help` (acpx included), the Grok/Devin/OpenCode model pins, the Agy pins against the ACP server's advertised ids, and the Agy preflight: acpx on PATH, the ACP server installed (its `VERSION`), no lane-changing keys in `~/.acpx/config.json`, and the server's Keychain login. Failed model listings never establish availability. Each configured OpenCode account gets one line: the store file exists and `opencode auth list --standalone --format json` includes a `credential` connection on the integration whose id is `opencode`. The check reads connection types only. OpenCode pins match exact keys in the JSON model API; the catalog is fetched at most once per provider per invocation, because a discovery read that fetched it records the ids (`client_ids`) or the failure class (`client_error`) and the pin check reuses them. The pin line also prints the provider verdict — `free`, `gone` (a failure) or `unknown` (not one) — and ready unpinned Zen offers print as advisory `new`. Doctor and discovery use a neutral directory and the selected provider’s scrubbed lane environment, with `--param directory=<cwd>` passed explicitly; the same API helper serves lane admission. Human model-list formatting is not a runtime contract. A listed but disabled/deprecated client model has a separate state, rather than advice to connect again. Discovery reads client metadata only for providers that returned eligible zero-price offers. It also checks the Claude subscription login and the native limit flags in `claude --help`, and probes Grok's configured native startup with `grok --sandbox off --cwd <scratch> version --json`, with no session or inference. This subcommand runs through startup/profile resolution; `--version` and `--help` exit earlier and cannot replace this probe. Tests pin argv construction and captured stream shapes; neither proves a live tool call. After a CLI upgrade, re-verify a changed adapter with a small complete packet on a capacity-eligible lane, in both placements (`--mode headless` and Herdr). The packet must exercise each permission the lane has and report each result: one shell command (lanes with a shell), one fetched URL (live web), one read-only MCP tool, and for Claude, which has no shell, one allowed file read and one refused read outside the workspace. A lane that happens to use no tool proves nothing about its permission flags. When the change is a version admission pin, run that packet from the source copy (`python3 -I <repo>/bin/xcheck run …`) with the new pin only in the working tree, and run `bin/xcheck install` only after both placements pass, so the installed runtime other runs use keeps refusing the unqualified version. Self-update is off in every lane: Codex `check_for_update_on_startup=false`, `DISABLE_AUTOUPDATER=1` for Claude, `GROK_DISABLE_AUTOUPDATER=1`.

### Codex

**Codex** runs its first-party headless stream: `codex --disable plugins --disable hooks --disable apps --disable computer_use --disable browser_use exec --skip-git-repo-check --ephemeral --sandbox read-only --cd <work> --model <model> --config model_reasoning_effort=… --config web_search=live|disabled --config check_for_update_on_startup=false [--config mcp_servers.<name>.enabled=false …] --json -`, with the message on stdin. `--ephemeral` keeps no session files and `--sandbox read-only` is the native sandbox (exec never asks for approval; a read-only sandbox still permits reads outside the packet). The disabled features are ones a review never needs: plugins bring their own MCP servers (a computer-use REPL among them), hooks can block a lane, and apps, browser and computer use act outside the packet. The operator's config otherwise loads, but MCP follows the review rule: before spending, the launch reads Codex's effective server list zero-turn (`codex mcp list --json` in the lane environment), disables every server that is not an approved keyless one (`semble`, `fff`, `qmd`, `pond`, plus `keenable-free`/`you-free` in live mode, each in the keyless shape Claude's rule requires and with no stored login: `auth_status` must be `unsupported` or `not_logged_in`, because Codex keeps MCP OAuth tokens the shape cannot show; the `Auth` column of `codex mcp list` shows them, and `codex mcp logout <name>` makes a free endpoint eligible again) by name, and reads the list again; if the list cannot be read or an unapproved server stays enabled, the lane is `skipped`. A call that still reaches an unapproved server (in packet mode the web servers count as unapproved) becomes a policy diagnostic when it starts (`item.started`), updated with its outcome on completion, so an abandoned call is still reported. Packet mode removes the web servers but is still not isolation. The installed `codex` is the runner's direct child and holds the pool descriptor itself. The answer is the last `agent_message` after the last tool item; `turn.completed` ends the turn and `turn.failed` fails it. A top-level `error` event is a recoverable notice (reconnects) and becomes the reason only if the turn never completes. Exec makes no title-generation call and needs no workspace trust entry. The real captured streams in `tests/fixtures/codex-*.jsonl` pin the reader.

The ACP form of this lane (acpx → the reviewed codex-acp automation build → Codex's app server) is kept, working and documented, on the `acp/codex` branch, last verified with codex-acp 2.1.1 and acpx 0.19.4. It was retired from `main` because the stock adapter reports failed turns as `end_turn` ([acpx#850](https://github.com/openclaw/acpx/issues/850)), persists sessions ([codex-acp#448](https://github.com/agentclientprotocol/codex-acp/issues/448)) and spends a separate title-generation turn, so it needed a local patch to match what `codex exec` already does. Revisit when upstream fixes those three (the branch's `integrations/codex-acp/README.md` has the retirement table): rebase the branch onto `main`, drop the patch rows upstream made unnecessary, and keep everything `main` gained since.

### Claude Code

**Claude Code** runs its first-party headless stream: `claude -p --restricted --strict-mcp-config --mcp-config <json> --disallowedTools mcp__claude_ai_* --permission-mode dontAsk --permission-prompts none --tools <built-ins> --allowedTools <built-ins,mcp__<server>…> --add-dir <work> --no-session-persistence --model <m> --effort <e> --debug-file <log> --output-format stream-json --verbose --include-partial-messages`, with the message on stdin and `DISABLE_AUTOUPDATER=1`. `--restricted` ignores settings files and hooks and confines file tools to the working directories (a read of `/etc/hosts` is refused). `--strict-mcp-config` with the inline `--mcp-config` registers only the validated local readers (`semble`, `fff`, `qmd`, `pond`) and, in live mode, the exact keyless `keenable-free` and `you-free` endpoints. A trusted local name must still have a keyless shape (stdio with only cache-location env, or loopback HTTP without headers), otherwise that server is dropped. `--disallowedTools mcp__claude_ai_*` removes account connectors even if the client loads them separately. `--tools` lists the built-ins (Read, plus WebSearch/WebFetch live) and `--allowedTools` pre-approves them and each registered server by name; `mcp__*` is not an honoured allow pattern, and without pre-approval a tool would prompt. Managed policy still applies. Never `--bare`: it skips the keychain and subscription auth fails. The installed `claude` is the runner's direct child and holds the pool itself.

Admission requires `claude auth status --json` to report a first-party claude.ai login in the scrubbed lane environment, and `claude --help` to list every flag above (the CLI upgrades on its own schedule). The `result` event ends the turn and carries the answer; with `is_error: true` that field is the error, even when `subtype` says `success`. A native error never publishes a draft or enters authentication recovery/retry. Bounded `Details: [code]`, `Request ID` and `Message ID` fields are retained in `provider_error` diagnostics and the reason notes; the full native result stays in the stream. A safeguard detail such as `reasoning_extraction` names the provider refusal, not a proven cause. The process exit may reflect runner cleanup after the terminal error and cannot establish an authentication failure. `system/init` lists each MCP server's startup status, and failed or needs-auth servers become diagnostics. Unapproved MCP calls are audited per `tool_use` id against their `tool_result`; a successful one is a prominent policy violation (billing unknown) that does not discard a contract-valid review. The real captured `tests/fixtures/claude-*.json*` streams pin the reader.

The ACP form of this lane (acpx with a local `--session-meta` patch → stock `claude-agent-acp` → the Agent SDK → `claude`) is kept, working and documented, on the `acp/claude` branch, last verified with claude-agent-acp 0.89.0 and xcheck-acpx 0.19.4-xcheck.1. It was retired from `main` because it added two layers over the same CLI with no gain for a one-prompt review: stock acpx cannot pass the controls (generic `_meta` passthrough was de-scoped in [acpx PR #32](https://github.com/openclaw/acpx/pull/32)), the adapter reads `defaultMode` from settings files even when the session excludes them, it releases almost daily, and Claude Code itself has no ACP mode ([claude-code#6686](https://github.com/anthropics/claude-code/issues/6686), not planned). Revisit if acpx gains generic `_meta` passthrough or Claude Code ships ACP natively: rebase the branch onto `main` and keep everything `main` gained since. The branch's `integrations/claude-acp/README.md` has the full table.

### Grok

**Grok** uses its native ACP server under stock acpx. Its [integration contract](../integrations/grok-acp/README.md) owns the detailed launch, isolated-home/auth-custody policy, plugin and MCP controls, tool identities, side-inference evidence and upgrade verification. Read it before changing this adapter. Review lanes use an unrestricted sandbox profile because the restrictive profile has failed native startup on symlinked container-runtime endpoints; shell writes remain instruction-scoped. Admission in `xcheck/grok.py` checks native startup and then `initialize` + `session/new`, without a prompt: the resolved toolset must match the declared review profile, hooks must be absent, MCP names must stay in the approved set, and model/effort must match. Unobservable or changed behavior fails closed. A different version alone does not fail admission. A fresh session's unavoidable initial title sampling remains outside `usage.json`'s main-loop call count; neither that counter nor a zero-turn admission probe certifies total billing for a review.

### Agy

**Agy** runs only through Antigravity's ACP server (`agy_acp_server.par` + `localharness_external`, the headless form Google ships for IDEs), driven by acpx, in both placements. `agy -p` ends the whole turn the moment it soft-denies a tool; the ACP server does not. The chain, outermost first: `acpx --no-terminal --no-fs --approve-all --prompt-retries 0 --format json exec --file <message>` (transport only; acpx's own client terminal would run commands detached, in any cwd, outside every sandbox, so it is never advertised) → `xcheck hold` (pool custody, above) → `sandbox-exec -f <lane>/agy.sb` → the server. The server refuses every tool and write without `--approve-all`, and its own terminal sandbox exists only under `oauth-business` admin controls, so the Seatbelt profile is the write boundary: writes are refused everywhere except the workspace, the lane's `gemini-home`, the Agy uv cache (`ROOT/.cache/agy-uv`) and `/dev`; the login Keychain is outside it. Re-verify with a lane that runs `touch` outside its workspace: `Operation not permitted`. Network stays open, so packet-mode web limits remain instructions. `GEMINI_HOME` is the lane's `gemini-home`: `antigravity-acp/settings.json` with `auth.type=oauth-personal` and `config/mcp_config.json` holding Claude's review servers in the server's shape (HTTP as `url`; it ignores `serverUrl` and `disabled`), minus `fff` (rejects the `server/discover` probe and fails the whole turn) and `qmd` (never finishes connecting over HTTP, and the server waits for every server). No hooks, rules or MCP from `~/.gemini` reach the lane. **The server never opens the Keychain.** Every Agy server xcheck starts (lanes and the zero-turn inventory probe) runs with `AGY_ACP_FORCE_FILE_STORAGE=1`, the server's own switch for its file credential store, and reads a 0600 copy of the login at `$GEMINI_HOME/antigravity-acp/acp_token.json`. The runner writes that copy from the canonical Keychain item (service `gemini`, account `antigravity-acp`, separate from the `agy` CLI's) through `/usr/bin/security` before spend, and deletes it when the lane settles. Provisioning and rotation must use a reviewed local helper through `security`, with the corresponding Keychain access control, rather than allowing the server to rewrite the canonical item. Why the server must not touch it: the server re-creates the item under its own Developer ID on every start, which drops every "Always Allow"; the next `security` write (a rotation) then makes the server raise a password dialog, and a dialog that outlasts the server's 3 s Keychain probe makes it fall back to an empty token file and open a Google sign-in in the browser. A missing, locked or token-less item, or a read that waits on a dialog, ends the lane `skipped` before admission. Create or switch that login through the reviewed local account helper; never sign in through the server against the canonical item. The optional `agy_rotate_command` integration is described in [local integration](local-integration.md). `TMPDIR` is the lane home (the server extracts its CA bundle there; denied, it drops the file in the workspace) and `UV_CACHE_DIR`/`UV_TOOL_DIR` point uvx-started MCP servers at the Agy cache, never the operator's. A server MCP failure arrives as a single-line whole answer `The MCP server '<name>' failed to initialize…` on a turn that ends `end_turn`; the reader fails the lane with that line; a review quoting it across multiple lines remains review text. A fixed-choice question to the user ends the turn (acpx exit 5) with no completion, so the lane fails. Neither `agy update` nor acpx installs or updates this separately distributed server. Obtain and verify both server files through the official ACP registry, then configure their directory locally. `doctor` compares the installed `VERSION` stamp with the [registry entry](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json) and prints an advisory `new` line when the registry lists another release; replace `agy_acp_server.par` and `localharness_external` together. A stale server or an unreadable registry never fails doctor. Dependency updates and signing checks are the adopting operator's responsibility.

### OpenCode

**OpenCode** (2.1.1) runs through its native ACP server and acpx, in both placements. The chain is acpx → `xcheck hold` → `opencode acp`, ACP takes the workspace from `session/new.cwd`; acpx and the runner already start there. V2 has no `acp --cwd` flag. The ACP server remains owned by the lane rather than the shared background service, preserving cancellation and pool custody. Here `opencode` is whatever the lane's PATH resolves first (an operator sandbox wrapper only if it wins on PATH). Zen and ordinary configured providers have no added permission rules, custom reviewer agent or config overlay: the stock `build` mode and existing user MCP/provider configuration remain. The former `--auto` approval behavior is carried by acpx `--approve-all`; `--no-terminal --no-fs` disables client-side tools, `--auth-policy skip` preserves stored login, and `--prompt-retries 0` prevents client retries. Web and packet-mode limits remain instructions. The native server has no OS sandbox of its own, and xcheck adds none. An adopting operator may use a separately maintained sandbox wrapper on PATH. It must exec the native binary and retain inherited pool descriptors; verify its filesystem and service-state boundaries independently. No such wrapper or updater is installed by xcheck.

A bare model becomes `opencode/<model>` (Zen); a `provider/model` reaches acpx unchanged, including OpenRouter’s `:free` suffix. An explicit effort is applied after model selection with `exec --config-option effort=<variant>`. It must be advertised by that model, otherwise startup fails before a prompt rather than downgrading. Left unset, the server selects the model's first and lowest variant (`minimal` or `low`, read zero-turn from `session/new`), so for an omitted effort xcheck reads the native `opencode api model.list --standalone` snapshot under the scrubbed lane environment and sets ACP's `default` value on models with variants, which leaves the provider's own effort; models without variants get no effort setting. A failed listing, or a model absent from it, ends the lane `skipped` (`startup-unavailable`) before spend. Both placements support explicit effort. No model substitution is enabled.

Provider-prefixed lanes retain only their existing provider env keys (`ZAI_API_KEY` and `ZHIPU_API_KEY` for Z.ai, `OPENROUTER_API_KEY` for OpenRouter). An empty required Z.ai key skips before admission. All `OPENCODE_*` overrides from the orchestrator are scrubbed. OpenCode has no quota meter, so its pools only serialize: each Zen model has its own (`opencode-zen-<model>`), so different free models run side by side across runs, and each other provider has one (`opencode-<provider>`), because its models share that account's limits. The lane remains opt-in with no protocol quota meter; a free model can still hit a provider limit. Zen has returned account quota refusals (`FreeUsageLimitError`, HTTP 429, native `provider.quota`), observed across that account's free models on 2026-10-21. This does not establish the only limiting dimension: upstream model and shared IP constraints can also affect availability. Reports of immediate 429s appear in [the upstream issue tracker](https://github.com/anomalyco/opencode/issues/43786); they do not establish a universal daily request count, reset time or a local outage. How soon a model recovers varies. A generic upstream 429 alone does not prove every model on that provider is exhausted. Optional local `opencode_accounts` maps account names to store paths (absolute, or starting with `~/`), and that object's insertion order is the round-robin order. An empty object is refused, as are two paths that resolve to the same file. `opencode_lanes_per_account` is a positive integer and defaults to 5. At launch, Zen lanes (a bare model or `opencode/…`) are dealt across those accounts. OpenRouter and Z.ai lanes stay on the native default store. The assignment is recorded in `run.json` under `accounts` and does not change later. The runner sets `OPENCODE_DB` to the assigned store after scrubbing orchestrator `OPENCODE*` variables. The admission `model.list` probe and the activity store reader use that same path. A run whose Zen lanes exceed `accounts × opencode_lanes_per_account`, or whose assigned store is not an existing file, exits 2 before `.launched` and spends nothing. A missing file would be created empty and the lane would run anonymously. With `opencode_accounts` omitted, lanes keep the native default store and the cap is not applied. Do not pin a lane with `opencode auth switch`: that switch is machine-global. Sign a store in with `OPENCODE_DB=<store> opencode auth login opencode --standalone --method device`. Do not pin a lane with an environment API key: a stored credential takes precedence over it, and I13 removes orchestrator `OPENCODE*` variables. Free Zen offers have refused custom permission/tool sets with `FreeTierError`, so ACP does not add any.

The shared ACP reader captures message chunks after the last tool call and requires the response to the observed `session/prompt` id with `stopReason=end_turn`. `cancelled`, `max_tokens` and `refusal` cannot publish a review. OpenCode’s terminal provider errors include `data.service=session`; a matching prompt error fails immediately even if later retry events continue. Its ACP event bridge does not expose intermediate native retry status; the native server can retry internally before its final error, as the previous `run` command did. `activity` retains the ACP session id so the existing workspace- and time-checked native store probe reads `session_v2` and assistant `session_message.content` and still reports tool/reasoning metadata. V1-only `session`/`part` rows cannot identify a new V2 lane.

OpenCode 2.0.32 translates native `provider.auth` errors into ACP's generic `Authentication required: provider authentication required`, dropping the provider's remedy. On a settled failed OpenCode lane, xcheck supplements diagnostics with the latest native assistant error's type, message and HTTP status only, after verifying the exact session's run time, workspace and model. When that message is a wrapper, the short provider sentence at `error.metadata.raw` inside the JSON response body is appended; the rest of the body, including account ids, and all headers stay out. Progress snapshots remain text-free. If the store cannot be verified, the ACP failure remains authoritative. An `api_key_expired` rejection requires a replacement key from OpenCode Console, saved through `opencode auth login opencode --standalone`; signing in again does not renew the expired key.

### Devin

**Devin** runs through its native `devin acp` server and acpx, in both placements. The special `--agent-type review` profile removes Fetch and MCP tools, so it is not used. The chain is acpx → `xcheck hold` → `devin --config <overlay> --permission-mode accept-edits --respect-workspace-trust false acp --model <pin>`. The model is pinned on the server command, not acpx: ACP advertises one family id (`swe-2-high`) and a separate `thought_level`, while the native `swe-2-max` selector initializes that family with Max effort. Passing `swe-2-max` to acpx rejects it as unadvertised; setting `swe-2-high` there can reset effort. Keep the full exact selector on Devin and confirm both config values in the startup stream after upgrades. SWE-2 Max was listed as Free by `devin models list` during the 2026-10-13 audit; recheck the selected offer before use. No refusal fallback is enabled.

The overlay preserves login, `org_id` and `shell.setup_complete` and empties hooks, so interactive permission hooks cannot hang the lane. It appends `exec` and `mcp__*` to `permissions.allow`, plus `Fetch(https://*/*)` / `Fetch(http://*/*)` in live mode; packet mode puts those fetch rules in `deny`. ACP session mode is explicitly set to `accept-edits` with `exec --config-option mode=accept-edits`, preserving the old app's workspace-edit permissions; `ask` removes shell tools. Native read-only, workspace edits and configured tools run without approval; acpx uses `--deny-all` for any remaining request, `--no-terminal --no-fs` so client-side tools cannot bypass the server, and `--prompt-retries 0`. `--auth-policy skip` lets the server use its stored login without acpx attempting an authentication exchange. Never `--cloud`; never the native `--sandbox`, which hid the login in the app path. The lane sets `DEVIN_PERMISSION_MODE=accept-edits`, sets `DEVIN_SANDBOX=false`, clears `DEVIN_REFUSAL_FALLBACK`, and sets `DEVIN_MODEL` to the pin. Shell writes and MCP/web limits remain instructions, as in the old app path; workspace-edit permissions do not sandbox shell commands. The lane stays opt-in and has no protocol quota meter.

### Herdr

**Herdr** (0.9.3). `pane list` gives each pane's `pane_id` and `terminal_title_stripped`; `pane layout --pane <id>` gives tab size; `pane split --pane <id> --direction right|down --ratio <share kept> --cwd <dir> --no-focus` returns `.result.pane.pane_id`; `pane run <id> <command>` types into the pane's shell (typeahead is buffered, so no readiness wait is needed); a pane closes when its process exits.

**Lane environment.** The orchestrator exports its session identity into every child shell (`CLAUDECODE`, `CLAUDE_CODE_*`, `CLAUDE_PID`, `CLAUDE_EFFORT`, `CLAUDE_PLUGIN_*`, `CODEX_COMPANION_*`, `CODEX_SANDBOX*`, `OPENCODE*`, `HERDR_*`). A peer that inherits them becomes a nested session of the orchestrator, runs at its effort, or can drive the operator's Herdr. Removing `HERDR_*` alone does not stop that: the `herdr` CLI falls back to its default socket, so the runner sets `HERDR_SOCKET_PATH` to a path that cannot exist and every `herdr` call in a lane finds no server. Native shells may read startup files that reintroduce credentials after environment scrubbing. xcheck sets `XCHECK_LANE=1`; any local secret loader must honor that guard and skip loading secrets for review lanes. xcheck does not install or modify shell startup files. Re-verify with a lane that counts API-key variable names without printing values: no key may remain except the selected OpenCode provider’s explicit allowlist. The runner removes them, every `CLAUDE*` name (the Claude adapter also reads `CLAUDE_CONFIG_DIR`, `CLAUDE_MODEL_CONFIG` and `CLAUDE_AGENT_*`), `MAX_THINKING_TOKENS`, `IS_SANDBOX`, every `ANTHROPIC_*`, `GROK_SANDBOX` and the redirecting `GROK_*` names, `OLDPWD`, every `ACPX_*` (acpx promotes `ACPX_AUTH_<X>` to `<X>` in the agent's environment), and every `*_API_KEY` except the provider key an opencode `provider/model` lane needs (`ZAI_API_KEY`, `OPENROUTER_API_KEY`), and sets `PWD` to the lane workspace: opencode roots its file tools and shell at `PWD`, not at its real working directory, so an inherited `PWD` points it at the orchestrator's directory. Harmless preferences such as `GROK_TELEMETRY_*` pass through. After the scrub, the runner sets `OPENCODE_DB` on an assigned Zen lane to that lane's store. Dedicated Kilo lanes also set their isolated `OPENCODE_DB` and generated `OPENCODE_CONFIG_CONTENT` as described above. Re-verify the inherited variable names without printing values, then run the fake-harness environment test.

OpenCode metadata startup retries a returned non-zero exit up to three times, with one-second pauses under the existing serialization lock. A missing executable, denied execution or 60-second subprocess timeout is reported immediately rather than repeating the same failed boot. This is an inference-free metadata retry, not a reviewer-turn retry. The published V2 standalone server holds an stdin ownership lease and exits on EOF even if its CLI owner is killed; [upstream implementation](https://github.com/anomalyco/opencode/blob/v2.0.27/packages/cli/src/services/standalone.ts) and [owner-death regression](https://github.com/anomalyco/opencode/blob/v2.0.27/packages/cli/test/standalone.test.ts) cover this mechanism. Do not add another cleanup group without a demonstrated escape from that lease.

**Configured instructions can reach peers.** Codex keeps the configured `CODEX_HOME` so subscription credentials are not forked; its global instructions may therefore reach a lane. Grok isolates `GROK_HOME`, references the original login through `GROK_AUTH_PATH`, and carries configured `[paths] extra_rule_dirs` by reference. This is a supported configuration surface, not a requirement to use any particular private rules layout. The lane message scopes inherited instructions to the review task, but does not make their contents private from that peer. Agy's isolated `GEMINI_HOME` carries no operator rules. Audit inherited instructions before admitting sensitive evidence; verify delivery using a synthetic non-sensitive sentinel, never by requesting a dump of private instructions.

**Independence.** Local commands and MCP tools can read outside the workspace, including another lane's result. Separate copies and the instruction prevent deliberate sharing, not adversarial reading.

## ACPX boundary

acpx (OpenClaw's ACP client, npm, on the official ACP SDK) transports the Grok, Agy, Devin and OpenCode lanes, unpatched. Its exec path passes its environment through, keeps the agent in its process group, kills the agent's tree on SIGTERM/SIGINT/SIGHUP, and holds an inherited descriptor itself but gives the agent only stdio. `xcheck hold` restores the server's pool custody.

What stays in xcheck for every lane: quota admission and pool locks, immutable packet snapshots, launch-once, the proof contract, environment scrub, answer selection and validation. An ACP `end_turn` is not a review: the reader selects the final message and `validate.check` decides. All ACP lanes refuse lane-changing acpx config keys before admission and disable acpx's filesystem/terminal tools (client capabilities only; each agent's own tools follow its native policy).

ACP standardizes transport and completion: initialization, sessions, prompt updates, tool/permission requests and the prompt response. It does not standardize OS sandboxes, credentials or proprietary configuration, so vendor policy stays explicit per lane: Grok profile + behavior admission, Agy Seatbelt, Devin overlay + accept-edits, OpenCode stock build mode. Optional features are negotiated. See [ACP overview](https://agentclientprotocol.com/protocol/v1/overview). Codex and Claude read their first-party streams instead: their ACP forms need third-party adapters, and those adapters needed local patches (see their branches under Harness facts). Never use acpx's built-in Codex/Claude names: they resolve npm caret ranges at launch.

## Deliberately absent

The retired predecessor (not a launcher) solved problems this design does not have. Do not re-add these without a failure that happened within scope:

| Legacy mechanism | Why it is not needed |
|---|---|
| Credit/auth log-regex classifiers over whole logs | their only consumer was the retry decision, and prose that quoted a token killed healthy peers; structured errors name the cause and nothing retries |
| Late harvest, file scouting, provisional labels, detached cleanup worker, notices file | lanes are owned processes that end with `exit.json`; one declared answer channel; the orchestrator reports from `STATUS.json` |
| Spender claims, PGID fallback, boot identity, daemon reaper, global lock with live-lane scans | every spender is our runner or its child; kernel lock lifetime equals spender lifetime; per-pool admission keeps disjoint pools parallel |
| Supervisor watchdog, pane-close and pane-ownership bookkeeping | the runner's alarm bounds it; `exec` makes each pane close with its runner |
| Herdr `agent start` readiness, splash classifiers, prompt resend | the prompt is a file acpx sends as `session/prompt`; a quiet turn remains pending unless a native failure or explicit cancellation is observed |
| Agy stdin bundle, 192 KB cap, read-depth probe | file tools reach large packets; the probe was gameable by grep |
| Agy app view, its trust entry, `ANSWER.ready` for Agy, its quota banner | Agy runs through its ACP server; the stream carries the answer and native completion |
| Host router, wait metrics, `LIVE_CHECK_CAP` gate | `--mode auto` places; token discipline is structural; the cap was a prompt contract, not enforcement. Read the shared protocol in full and linked integration details when changing that boundary; document size is not assumed to fit a single tool response |
| Perplexity lane | not a supported reviewer transport |
| An opencode reviewer agent or permission rules | the free tier refuses custom permission/tool sets; its workspace and retrieval restrictions remain instructions, and the dropped Seatbelt profile is not a boundary |
| Codex app view, `-o` fallback and trust editor | the exec stream's last `agent_message` is the answer (real captures always carry it), and exec needs no trust dialog or operator config write |
| Claude/Grok app views, `--view`, `ANSWER.md`/`ANSWER.ready` commitment, screen logs and limit-banner handling | every lane streams structured events in both placements; native completion is the only publication signal |
| Devin/OpenCode app views, `ANSWER.ready` for these lanes | Native ACP completion supplies the final answer in both placements |
| Runtime inside a writable source tree | installation publishes a read-only content-addressed snapshot outside the checkout; verify host permissions separately |
| Snapshot pruning | a queued runner may still exec an older snapshot |
| Fallback quota meters (Agy language-server port scan, CSRF probing, desktop-token scraping; Grok monthly view), an outer retry layer, secret redaction of notes | each pool's one meter works; an unreadable meter fails closed; notes never carry payloads or tokens |

Proposals already rejected, with the reason:

| Proposal | Why not |
|---|---|
| Isolating a home by copying or abandoning canonical authentication | forks auth/refresh custody. Codex keeps its home; Grok isolates `GROK_HOME` while `GROK_AUTH_PATH` references the canonical login. Agy uses its deliberately disposable file credential copied from the canonical Keychain item, with the refresh limitation recorded in [Current limits](../Multi-Agent%20Cross-Check%20Protocol.md#current-limits) |
| Remove Claude `--allowedTools` | `--tools` only lists tools; `--allowedTools` is what pre-approves them |
| Kill an orphan when `ps` is denied | PID reuse can kill an unrelated process |
| Shell-readiness wait before `pane run` | typeahead is buffered; a miss surfaces as `failed` |
| Scrub loader variables (`DYLD_*`, `PYTHON*`) | the installed copy runs `python -I`, and the Codex rule matches only the exact command |
| A bare `xcheck` pattern in the Codex rule; allowing `lane`/`install` | PATH hijack; those are not orchestrator commands |
| Automatic retries | a quota/auth death repeats; a bad packet needs a fresh BASE |
| Require the same served-model assertion from every harness | native evidence differs. Cline completion must name the exact requested model/provider; Grok's admission checks the session model/effort. Other streams do not uniformly attest the serving model. Every lane passes its exact selector and no fallback flag; never infer unavailable identity evidence |
| Hide lane names from the orchestrator during the merge | lane identity is evidence the merge uses (measured lane reliability and same-family correlation matter), style names the lane anyway, and the orchestrator's bias runs toward its own work, which no label hides |
| Paraphrase or style-normalise answers to hide authorship | light perturbation helps, but full normalisation lets agreement with the judge's own views take over as the preference (arXiv 2512.05379), and a paraphrase can change what a finding claims |
| A self-preference warning in `PROMPT.md` or the merge | a one-line bias warning did not move self- or perceived-authorship effects when measured |
| Replace acpx with an in-house ACP client | it would delete `xcheck hold` and the acpx config guard, but xcheck would then own handshake, model and config-option selection across ACP revisions, and permission answers: the protocol layer acpx (on the official ACP SDK) maintains |
| Return Agy, Devin or OpenCode to their native CLIs or apps | `agy -p` ends the turn on any soft-denied tool, the apps need `ANSWER.md` commitment and can block on dialogs, OpenCode's app took no effort; ACP gives each a structured stream with native completion in both placements |
| Run Codex through codex-acp on `main` | the stock adapter reports failed turns as `end_turn`, persists sessions and spends a title turn; `codex exec` has none of these, so the ACP form waits on the `acp/codex` branch for upstream fixes |
| A direction-tagging acpx patch, or one patched client for every lane | the ACP shape already identifies prompt completion, and an id collision is resolved by the other response or by acpx's own exit; a second patch would add maintenance for no in-scope failure |
| A pre-prompt Grok `_x.ai/session/rename` to skip title sampling | verified on 1.0.50: the initial title is still sampled and discarded |
| Let peers rank each other's answers (council stage 2) | a judge favours its own entry even when anonymised, and a ranking is a preference, not a falsifiable finding |

## Repository

The execution core is `run.py` + `lane.py`, with outcome/publication policy in `settlement.py`. Shared values and environment policy live in `types.py` and `environment.py`; Grok admission and Agy inventory live in `grok.py` and `agy.py`; `doctor.py` reports those same checks. `tests/test_settlement.py` covers display-failure isolation, termination precedence through publication failures and recovery, known spawn refusal, immutable terminal records and read-only status observers. See [Runtime architecture](architecture.md) before changing ownership boundaries.

`uv run --python '>=3.12' --with-requirements requirements-test.txt pytest` (about 25 s on all cores; `pytest.ini` sets `-n auto`) and `git diff --check`. Runtime is Python 3.12+ stdlib plus the harness CLIs; there is no venv or lockfile — the runner command supplies the test dependencies in `requirements-test.txt` (Hypothesis, pytest, pytest-xdist). The suite is unittest classes; each test owns its `XCHECK_ROOT`, pools and fakes, so they run in parallel safely. Optional long acceptance: `uv run --python '>=3.12' --with-requirements requirements-test.txt pytest tests/acceptance_runtime.py` runs one isolated installed fake turn silent for 185 s and checks valid publication and pool release.

`tests/fake/harness` fakes `codex exec` and `claude -p` (`native_turn`), acpx and every ACP lane's server (`review_turn`), the capacity meters and the Keychain lookup; one set of modes drives both turn functions. `tests/test_xcheck.py` holds ACP correlation (`AcpCorrelation`), the Claude per-call audit and MCP boundaries, end-to-end runs, pools, Herdr ownership, capacity and validation; `tests/test_runtime_e2e.py` drives an isolated installed runtime through silent work, drafts before completion, explicit limits, cancellation, detachment and reattachment; `tests/test_final_repairs.py` guards terminal-answer precedence, spawn/setup cleanup, orphan identity and recovery, immutable queued inputs and compact activity; `tests/test_claude_auth.py` exercises native authentication recovery, abrupt runner death, blocking admission probes, concurrent recovery and the Terminal helper; `tests/test_codex.py`, `tests/test_claude.py` and `tests/test_*_acp.py` cover each lane's chain, custody, controls and admission; `tests/test_view.py` checks the pane transcript against captured streams; `tests/test_laws.py` holds property laws for the answer grammar. `tests/conftest.py` gives every test session a disposable `HOME` (with only a Grok login stub and the fake Agy server) before `xcheck` is imported, so no test reads or copies the operator's configs, and refuses Python older than 3.12; tests also set `XCHECK_ROOT` to a disposable root. Never point a test at the real `/tmp/agent-offload`: it would queue behind live runs. If a file-sync service resets executable bits, restore `755` on `bin/xcheck` and `tests/fake/harness`.

After changing `bin/` or `xcheck/`, run `bin/xcheck install`, then `xcheck doctor`. History is `git log`; durable requirements, invariants and limits live in [the protocol](../Multi-Agent%20Cross-Check%20Protocol.md), not in TODO or ledger files.

Native progress is diagnostic, never a termination or time-extension predicate. `activity` records event types and completed-tool counts without arguments, results or answer text. OpenCode additionally reads its local native store only after checking the exact session belongs to this lane workspace and was created for this run; it reports tool state and reasoning length/timestamps. An open tool can buffer output, and reasoning can advance without a completed stream part. Compare metadata to learn what changed; an unchanged snapshot is unknown. A corrupt message or part is skipped without discarding verified metadata from other rows; partial or unavailable native diagnostics are shown explicitly. Equal timestamp rows use sequence order. Native running metadata survives process death, so always pair it with current runner liveness. A blocked permission prompt remains pending until an explicit intervention; never resend the task or infer failure from CPU, spinner paint or missing heartbeats.
